## 一、要你先定的

### 定 1. 节奏目标按谁判

- **现状**：`week_cycle`（一周到第 7 环）只由 `greedy` 判，它每小时动一次。同一个机器人每 4 小时动一次只到第 3 环，每 8 小时一次第 2 环；按 `week-decay` 日程（33 次回访）的 LLM 玩家第 1～3 环。
- **两种选法**：
  1. 目标不变，让玩家不在线时也能推进（做 A）。v2 的数值是按每小时操作调的，A 做好以后，玩家的体验会向这套数值靠拢，大部分门槛不用重调。
  2. 目标改成“按日程上线的玩家一周到第 r 环”，按 33 次回访重调进环时间、敌人强度和经济。改动面大，v2 的读数要重来。
- **建议**：选 1，同时做 I，用按日程的参考机器人复测。

### 定 2. 推进规章默认开还是作为解锁

- `docs/design-v1.md` 的原则是“地图的形状只在玩家在场时改变……或由玩家事先写好的规章代为确认”，推进规章不违背它。
- **默认开**：轻度玩家马上受益（这批里打分最低的就是轻度休闲，2.42）。
- **作为解锁**（组织等级、学说或见习任务）：本身是一次“自动化解放”的爽点（设计表里“做 2 到 3 条规章”），但第一轮的玩家可能拿不到，而第一轮正是现在唯一测过的。
- **建议**：第一轮就给（见习任务奖励或开局自带），以后的轮回再解锁更强的版本（比如“只打预演余量大于 x 的格子”“优先连片”）。

### 定 3. 晶体的定位

- v2 把晶体从“没用”变成军械突破的必需品。现在晶体只从裂隙来，种子之间差很远：失守率 0.05～0.54，取决于早期有没有晶体去突破民兵操练；精算规划有两局一周晶体都是 0。
- **两种选法**：晶体当稀缺的瓶颈（玩家要专门去打裂隙），配合 B 把来源写清楚；或者当常规资源，给稳定来源（D）。
- **建议**：两样都做一点：守住来潮按环给少量晶体做保底，裂隙仍是大头；民兵操练的突破不要晶体。

### 定 4. 高潮放在哪

- 现在最后一天没有全轮最大的爽点（`finale` 0），大爽点集中在第 1、2 环的占领。
- v2 文档的提议是把异界核心（第 7 环）做成最后一天的高潮，但玩家一周只到第 2～3 环。
- **建议**：先做 A，再看玩家能到哪一环；高潮跟着“这一轮最深的那一环”走，而不是写死第 7 环。

## 二、游戏本体

### A. 推进规章（高）

- **问题**：小队把路线来回走，路线上的格子被自动占领以后，小队只巡逻，等玩家给新路线。`greedy` 每局改路线约 150 次，扩张征服 3 局一共 81 次；轻度休闲 25 次写“只在领地里巡逻”（第 25 条）。
- **建议**：新规章“推进”：小队路线全在领地里时，改走预演能赢、离领地最近的前线格（规则和评估机器人的 `route_for` 一样）。打不赢就不动，并在局面里说“没有能赢的前线格”。
- **改哪层**：
  - 机制层：规章的判断和改路线，规章 id 登记在 `data/hooks.rs`；
  - 数据层：规章条目；
  - 本地化：规章名、说明、事件；
  - 客户端：文字版和网页都显示规章开关和“自动改了路线”的事件；
  - 评估：新事件 key 归类到 `payoff_classes.json`，机器人可以改用它代替自己改路线。
- **怎么验证**：
  - `greedy@4`、`greedy@8` 开着规章，领地应接近每小时的 `greedy`；
  - 按日程的参考人格（I）；
  - 轻度休闲和扩张征服各 3 个种子复测，看“回来什么都没变”和推进顺畅的打分。

### B. 把跨系统因果写进局面（高）

这批四种性格都提到，改动只在客户端和文字，便宜（第 16、26 条）。

- **晶体从哪来**：军械卡在突破时，在突破那一行写“晶体来自镇压的裂隙，最近的裂隙在 X”；网页现在只在地块面板的悬停说明里写了。
- **每小时收入为 0**：收入行旁边说明“小队带回的不算在内”，以及哪几座设施没人上岗、为什么（工人被民兵、哨所占走）。
- **组织经验**：局内显示“本轮结束时预计获得 n 经验”，不要一整轮都是“Lv.1，经验 0”。
- **反应图鉴的用语**：“传闻”写出是哪两种标签的组合，“挂层”“发作”“接得上”在第一次出现时给一句解释。
- **住房和居民**：无处安置时说明是哪座设施占了住房、加哪种建筑能解决。
- **轻度玩家**：局面开头给一行“最该做的一件事”。轻度休闲只挑菜单最上面一两项，现在的菜单顺序不保证最上面是最要紧的。
- **怎么验证**：文字版的局面快照；下一批 LLM 试玩“看得懂”的打分（现在四种性格多数是 2）。

### C. 告急格（中）

- **问题**：扩张征服终局告急 10～25 格，失守率 0.34；“守城和来潮之间的因果说不清”，菜单里只看到“放弃”（第 15 条）。
- **建议**：告急时列出能做的事和各自的代价（派谁驻扎、反击的预演、放弃会丢什么）；扩张前在路线预演里提示“占下以后要守的边界多 n 格”。
- **改哪层**：客户端为主；预演里要多一项“边界变化”，机制层的预演接口要补。

### D. 晶体的来源和突破（中）

- **问题**：`defense`（失守 0.27，目标 ≤ 0.25）和 `economy_flow`（最长无事可花 6 小时，目标 ≤ 4）两道门槛都卡在晶体上（v2 六.2、六.3）。
- **建议**（按定 3）：守住来潮按环给少量晶体做保底；民兵操练的突破不要晶体；或者突破允许多花废材顶一部分晶体。
- **改哪层**：数据层（`balance.json`、军械表），可能要一个新效果种类（来潮掉落）。
- **怎么验证**：`eval run greedy` + `eval review`，看 `defense`、`economy_flow` 和种子之间的离散。

### E. 第 24 小时前线胜率非 0 即 1（中）

- **问题**：`combat_gate` 的 `frontier_win.h24` 每个种子非 0 即 1，因为同一环各格难度差不多；难度台阶主要来自 `mapgen.rs` 里写死的波数、人数（v2 六.1、六.7）。
- **建议**：把波数、每波人数挪进 `balance.json` 按环查表，让第 3→4 环的台阶变缓；或者打开巢穴强度（已做，默认关）并放宽范围。
- **改哪层**：数据层 + 机制层（地图生成读表）。按 CLAUDE.md，这类常数本来就该在 `balance.json`。

### F. 后几天的大爽点和终局高潮（中）

- **问题**：`peak_rank` −0.78、`finale` 0（`greedy`）；玩家后四天惊喜 0.15～0.54（第 5、6 条，v2 六.4）。
- **建议**：按定 4，高潮跟着这一轮最深的环走；第 5 次以后的军械突破升为“大”级；推进规章开着时，“回来地图又大了一片”本身就是回访的收获。
- **依赖**：A 和定 4。

### G. 三条测价为 0 的学说（低）

- 悬赏令、壁垒、汲取的测价是 0（v2 六.5）。悬赏令和汲取依赖标记和标签消耗，测价队伍里没有对应的写手；壁垒的护盾按理该有效，要查是开战标签的读法还是测价遭遇太短。
- **改哪层**：先查评估（`price` 的测价队伍和遭遇），确认是工具的问题还是学说本身没用。

### H. 规则和设计不一致的小问题（低）

- 第 11 条：打输的反击照样计反应和图鉴。建议预演判输时不允许反击，或打输不计反应。
- 第 19 条：锁定只挡退役。等有了批量操作再一起做。
- 第 20 条：共居条例不开混合职业，和设计不一致。要么改设计文档，要么加一个异界混合职业。

## 三、评估工具

1. **按日程动手的参考人格（高，I）**：人格现在只支持“每 N 小时”，加一个按 `week-decay` 日程动手的 `greedy`，节奏类门槛（`week_cycle`、`every_visit`、`economy_flow`）改由它判，或者两种都跑、分别给区间（eval-status 二.7）。这是验证 A 的前提。
2. **人格基线（高，J，进行中）**：
   - 五个人格在 v2 上重跑，`builder`、`explorer` 跑完了，`turtle`、`scholar`、`tactician` 还在跑。
   - 初步读数：`builder`（经济优先）现在成果 1500、失守 0.11，都比 `greedy`（1198、0.27）好，和第 22 条“经济优先最差”正相反。
   - `explorer` 在 v2 上第 48 小时以后领地停在 16 格，查出是机器人的问题：先打最深时只看最深的 12 格，打不赢就退回去打最深那格。已修（提交 76c5405），重跑后领地 16.5 → 94.5 格、成果 180 → 886，8 个种子里 7 个第 56 小时左右到第 5 环。
   - 跑完以后：对照 `greedy` 并排、写成新基线，更新第 21～24 条和 v2 文档六.6。
   - `builder` 一次跑了 23 分钟（`explorer` 73 秒）：经济优先不补民兵，几乎每小时都在丢格子，防守推演每小时最多 36 次、每次推演 12 小时。要么给推演设上限，要么缓存同一小时的推演。
3. **多轮运行和轮回指标（中，K）**：机器人第 168 小时收束、接着玩下一轮；组织经验、到 2 级和 3 级用几轮、第 k 轮的进环时间（eval-status 二.1）。B 里的“组织经验看不见”也要靠它量。
4. **换模型对照（中，L）**：同一版本让 Sonnet 扮一种性格（建议精算规划，和上一批对得上）；做完 A、B 以后再跑一批 Haiku，看改动对玩家的效果。
5. **节奏模型补军械、资源按来源记账（中，M）**：`eval pace` 和 L0 遭遇曲线还没有军械；情报的三个来源没分开记（eval-status 待办）。
6. **搜索型人格和选择分叉（低，N）**：随机合法策略或进化搜索找漏洞和最高打法；在选择点分叉比结果（`eval choice`）。
7. **小问题（低，O）**：
   - 会话行动里不认识的字段被静默丢掉，应该拒绝并说明（轻度休闲种子 2 把打分放进了 `feel`，这次没丢数据）；
   - 网页没有评估，只靠文字版和文字快照对齐（eval-status 二.8）。

## 五、建议的顺序

1. 你定“定 1”“定 2”（建议：目标不变 + 推进规章第一轮就给）。
2. 并行做：
   - A 推进规章 + I 按日程的参考人格；
   - B 可读性（只动客户端和文字，和 A 不冲突）。
   - 同时把 J 的人格基线跑完、写成新基线。
3. 复测：`greedy` 每小时、按日程两种，加一批 LLM 试玩（四种性格各 3 个种子，再加一组 Sonnet）。看玩家的领地、打分是不是向机器人靠拢，“看得懂”有没有从 2 往上走。
4. 按复测结果做 D（晶体）和 C（告急），重跑门槛。
5. 再做 E、F、K（第 24 小时胜率、高潮、轮回评估）。
6. G、H、M、N、O 穿插在中间做。
