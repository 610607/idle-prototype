# 设计 v2：引擎模型（记录稿）

2026-11-28。讨论中的记录，**不是最终版**，还没实现。[总纲](design-v2-outline.md) 里“设计语法”往引擎方向的展开：让语法成为引擎里真正的类型，游戏机制作为接口挂在上面。定稿后再并进总纲、[架构](architecture.md) 和 [计划](design-v2-plan.md)。

每一条都标了状态：**已定**是设计者确认过的，**提议**是还没确认的，**在谈**是正在讨论的。

## 已定

### 方向

- 设计语法成为引擎的类型，战斗、经营这些机制是挂在上面的接口。不做通用的规则解释器。
- 和五层对应：语法进引擎层，接口声明和反应表进数据层，接口的实现进机制层。

### 实体和数量

| | 是什么 | 有哪些 |
|---|---|---|
| 实体 | 有身份、标签、属性表、状态，声明若干接口 | 队员、敌人、建筑、装备、条令、政策、部门、小队 |
| 数量 | 没有身份和位置，只是数 | 资源、普通居民 |

- 普通居民按数量算，被招募成队员时才变成实体。
- 消耗品是实体，用掉以后消失。

### 接口

实体在数据里声明接口，每种接口带自己的一块数据。

| 接口 | 对应动词 | 声明了它的实体能做什么 |
|---|---|---|
| 可放置 | 摆 | 进城市格子的槽，和邻格、街区碰 |
| 可出战 | 摆 | 进队伍的槽，参加战斗 |
| 可行进 | 走 | 沿路径依次经过位置 |
| 可经过 | 走 | 被路过时发生什么 |
| 可装配 | 摆 | 进宿主的槽，把标签和修正给宿主 |
| 可转化 | 变 | 能变成什么，标签怎么带过去 |
| 有槽位 | — | 自己是容器，声明每个槽收哪种接口 |
| 计分 | 亮和藏 | 显露和收起时各按多少计入分数 |

- 一个实体可以声明多个接口。同时声明“可出战”和“可放置”的特殊队员可以当建筑。
- “碰”不是接口，是标签和反应表，所有实体共用。

### 装上去就是摆

装备、条令、政策、部门、队员、建筑是同一件事：一个实体进了宿主的槽。

| 东西 | 宿主 | 槽 |
|---|---|---|
| 装备 | 队员 | 装备槽 |
| 条令 | 小队 | 条令槽 |
| 政策 | 街区 | 政策槽 |
| 部门 | 总部 | 部门位 |
| 队员 | 小队 | 前后排 |
| 建筑 | 格子 | 建筑位 |

- **修正的流向**：槽里的给宿主，相邻的互相给。
- **交换**：两个实体互换槽，条件是双方都能进对方的槽。所以两名队员能换、两座建筑能换，队员和建筑不能换，除非那名队员也声明了“可放置”。
- 交换可以是一种效果（例：特殊队员给两个实体挂上标记，定期交换它们的位置）。自动交换守手动的限制：告急格上的建筑、战斗中的队员不能换。

### 属性和状态

| | 是什么 | 例子 | 规则 |
|---|---|---|---|
| 属性 | 算出来的 | 生命上限、攻击、产量 | 基础值加上槽位和邻格给的修正，随时重算，不存档 |
| 状态 | 留下来的 | 当前生命、标签层数、冷却 | 一直留着，直到被“碰”清掉，要存档 |

- 每个实体带一张属性表，属性的词汇在数据层定义。接口声明它要读哪些属性。
- 所以建筑可以有攻击：声明“可出战”并填上属性。现在守城建筑在战斗里出手是特例，改成正式声明。
- 界面只显示实体声明了的接口对应的属性。

### 品质

- 可装配的实体都带实例，包括条令和政策，不限一份。
- 出产有品质差异。提议分三档、只影响数值大小、同名同档可以合成高一档（合成和档数是**提议**）。

### 战斗

- **战斗是两个分组进了同一个战场，按回合互相碰，直到一方没人站着。** 进攻、守城、切磋是同一件事，只是分组的来源不同；敌人打敌人也成立。
- 专用代码只剩回合调度：谁先动、一回合几步、何时结束。回合里发生的事用通用的效果句式写。
- 城市产出的公式仍是专用代码，读同一套标签和属性。

### 效果的句式

条令、装备词条、建筑联动、政策、特殊队员的能力、敌人的行为规则，都用同一种句式写。每段是一张封闭的清单。

| 段 | 内容 |
|---|---|
| 时机 | 进槽时、被路过时、每隔多久、回合开始、受击时、某标签叠到几层时 |
| 条件 | 可选。生命低于多少、对方带某标签等 |
| 对象 | 自己、宿主、相邻、同分组、带某标签的 |
| 结果 | 一个有顺序的列表，依次执行：改属性、加减标签、改状态、移动实体、转化、增减数量 |
| 代价 | 行动点、被动点、数量 |

- **不做语法上的嵌套。** 复杂效果靠两种办法拼：
  - 事件接力：一条效果的结果产生事件（标签被加上、实体被移动、有人倒下），别的效果拿它当时机。
  - 标签当计数器：要记住发生过几次的，用标签层数记。
- 例：“多次现场复活后获得锁血一次”是两句。被现场复活时给自己加一层标签；该标签叠到三层时转化成锁血词条。
- 遇到拆不出来的效果，加一种结果类型，不改句式。

### 行动点和被动点

- 是效果的代价。战斗里花行动点（主动）或被动点（被动触发），战斗外花数量。
- **被动点给连锁反应封顶**：花完连锁就停，另有一个硬上限。这保证战斗确定、预演算得完。
- 每场重置，不跨战斗保留。
- 声明“可出战”的建筑也有这两项。

### 其余几条

| | |
|---|---|
| 生产和消耗 | 不加第六个动词。产出是一种结果，时机是“每隔多久” |
| 格子 | 是实体：有槽位、可经过 |
| 已知程度 | 每个实体对玩家有：未知、有迹象、看清。和“亮和藏”是两回事 |
| 常设指令 | 战术规则、用药线、自动摆放、钉子是玩家留下的指令，挂在实体或分组上，句式和效果相同。自动化的每一层就是开放一种指令 |

### 颠覆规则的内容靠解锁逐步出现

- 引擎从一开始就支持跨接口的实体和交换这类效果，但**头几局的内容里没有它们**。能当建筑的特殊队员这类东西，随轮回和解锁才出现。
- 所以新玩家接触到的每样东西都只走一种接口的常规用法；例外一次只来一个。

### 容器和分组是一回事

- **分组就是容器。** 容器只分两种：成员有位置的，和成员没有位置的。
- 有位置的：棋盘、小队（前后排）、战场、装备槽这类。没有位置的：街区、阵营、敌人的族。
- 成员怎么来有三种：进了槽、玩家圈定、按规则自动判定。
- **归属就是阵营这个容器**，占领和俘虏是换阵营。
- **容器没有专门的行为，行为都是效果。** 街区属性、政策对街区内建筑的加成、条令对队员的加成，都写成挂在容器上的句子：满足什么条件，对哪些成员，产生什么结果。容器只需要提供成员名单和成员标签的合计，供条件和对象去读。
- 战斗的双方是两个有位置的容器。

## 提议，还没确认

- 守方的站位（计划阶段 5 暂按这个写）：每个街区有一个守备阵型（前后排），玩家或自动摆放把建筑、民兵、驻扎队员排进去；街区的任何一格被打，都由这个阵型应战。

### 一局多长，局外放什么

设计者 2026-11-28 提出：颠覆规则的内容既然靠多局解锁，每局就要缩短，局外内容要增加。已定：**第一局大约一小时**，之后随解锁逐局变长；头几局坐着玩，经营到第三、四局才展开；计划按局来切。已并进总纲和 [计划](design-v2-plan.md)。要点：

- 一局的长度不写死，仍由分数平台决定；头几局解锁的系统少，平台来得早，局就短。解锁越多，一局越长。
- 局外的成长以拓宽选择为主（新的实体种类、接口组合、难度条件、开局配置），数值上的加成只用来压缩开局，且有上限。
- 解锁主要靠第一次做到某件事（打下某个核心、用某种打法到达平台），其次才是累计分数。

## 以后再定

- 一个实体能同时在几个容器里。设计者：暂时不用确定。
- 修正往上传几层（装备给队员，队员给小队，再往上）。
- 加法和乘法的顺序；同时发生的几次“碰”按什么顺序算，要保证确定。
- “收起”具体有哪些：库存是一个容器，在库存里就是收起；带伤是状态。
- 实例怎么生成：掉落、招募、抽卡时品质和名字怎么掷。
- 跨局带走可以做成一个容器，名额是它的槽。
- 每种结果都要能无副作用地模拟，统一预演才做得出来。
- 解锁条件的写法，可以复用“时机”的清单。
- 标签、属性、槽各有哪些，跟着各阶段定。
