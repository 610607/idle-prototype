# LLM 试玩：Haiku 和脚本玩家并排

2026-11-27。起因：脚本玩家研究和不研究差别很小，可能是脚本只会写死的打法，测不出要「想到」才用得出来的条令组合。于是加了一个文字版，让 Haiku 每 4 小时看一次文字局面、选动作，和脚本玩家在同样的种子、同样的节奏下并排跑；顺便看局面信息够不够让新玩家看懂。

## 怎么跑

文字版的逻辑在 `engine/src/textui.rs`，文字在 `locales/zh-CN/cli.json`，命令行是 `engine/examples/agent_cli.rs`：

```bash
cargo run --release --example agent_cli -- new <存档> <种子>
cargo run --release --example agent_cli -- do <存档> 1 3 --wait 4 --note "理由"
cargo run --release --example agent_cli -- info <存档>
cargo run --release --example agent_cli -- autoplay <存档> <种子> 72 4
```

- 局面：资源和产出、电力、关注度、领地和告急、未来 12 小时来潮预报、本轮成果和明细、15×15 字符地图、小队、队员（一行一人，写/读哪些标签）、条令和反应图鉴、街区、这段时间的事件、待你决定。
- 菜单由引擎的预演生成：路线（带预演胜负）、驻守（只列预演守得住的）、反击、建设施（带预演差异）、研究和三选一、招募（只列付得起的）、政策。菜单外可以 `--route` 自定路线、`--json` 发任意命令；`info` 末尾有全部命令的 JSON 样例和说明。
- 两边都开着三条规章（稳妥占领、择优招募、告急反击），见习任务奖励自动领。`AGENT_NORESEARCH=1` 做对照组：菜单里没有研究，`--json` 发研究命令也会被拒。
- 每个 `do` 记一行 JSONL（`<存档>.log`）：选了什么、结果、玩家写的理由、之后的摘要。
- Haiku 只许用这个工具，不读仓库。72 小时，约 18 个决策点。
- 同时最多跑 3 局（3 个子代理，见 `CLAUDE.md`），多局分批跑。

以后的试玩用**会话**（协议见 `docs/eval-interface.md`，逻辑在 `engine/src/textui/session.rs`）：回访时刻由日程定，玩家不能自己选等多久；菜单项用由命令内容算出的 id，旧 id 只会被拒绝；每次回访记一个感受，阶段结束后的第一次回访先打分；结果落成会话目录，给 `eval session` 重放算指标。

```bash
cargo run --release --example agent_cli -- session new <目录> --seed 0 [--schedule week-decay|every:N] [--hours 168] [--player haiku] [--no-research]
cargo run --release --example agent_cli -- session obs <目录> [--json]
cargo run --release --example agent_cli -- session act <目录> --pick a1b2c3 --feel flat --why '一句话' [--score growth=3:'依据' …]
cargo run --release --example agent_cli -- session serve <目录>    # 外部程序驱动：一行观察 JSON 出，一行行动 JSON 进
```

- 默认日程 `week-decay`：168 小时，第 1 天每 3 小时、第 2～3 天每 4 小时、之后每 8 小时回访一次，共 33 次；第 24、72 小时和终局要先打分（八个维度，1～5 分）。
- 被拒的行动（id 不在菜单里、感受标签不对、该打分时没打齐）不改变任何东西，同一次回访的观察会把原因写在最前面；引擎拒绝的单条命令只算这次回访里失败的一项。
- 命令参考还是 `agent_cli info <目录>/save.json`。

跑了两轮。第一轮之后修了文字版漏掉、网页上有的信息（建设施的预演差异），又给引擎的预演差异加了「住房」一行，再跑第二轮（含不研究的对照组）。

## 结果（第 72 小时）

| 玩家 | 种子 0 | 种子 1 | 种子 2 | 平均 |
|---|---|---|---|---|
| 脚本，每 4 小时，研究 | 220（19 格） | 111（20 格） | 192（19 格） | 174 |
| 脚本，每 4 小时，不研究 | 223 | 102 | 192 | 172 |
| 脚本，每小时，研究 | 322（41 格） | 226（41 格） | 281（41 格） | 276 |
| 脚本，每小时，不研究 | 315 | 227 | 268 | 270 |
| Haiku 第一轮，研究（各 2 局） | 152 / 122 | 113 / 120 | 119 / 95 | 120 |
| Haiku 第二轮，研究 | 140（7 格） | 138（5 格） | 127（5 格） | 135 |
| Haiku 第二轮，不研究 | 178（11 格） | 115（5 格） | 94（5 格） | 129 |

数字是「本轮成果」，括号里是领地格数。

- **研究在 72 小时内几乎不改变结果**，脚本（+1%）和 Haiku（135 对 129，单局从 94 到 178）都一样。
- **Haiku 比同节奏的脚本差**（9 局研究组平均 125，脚本 174），领地停在 5–12 格，脚本 19–20 格。
- **Haiku 也没有找到条令组合。** 9 局研究组第一条都选「反应协议」，7 局第二条选「电离标定」，基本是跟着卡上「接得上」走；反应图鉴最多点亮 1 个（锁定），5 局一个没点亮。没有人为了触发新反应去换阵容。脚本同期点亮 1–3 个。

## 为什么

1. **72 小时内卡住的是人手和守城，不是战斗强度。** 第 1–2 圈的路线战本来就赢，条令改的是战斗规则，没有用武之地。两种玩家都一样，所以研究组和对照组没差别。
2. **Haiku 把人手用光了。** 它们把 3–4 名队员轮流派去驻守预报会失守的格子，小队被抽空以后探索就停了。脚本只拿闲人驻守、小队一直保持 3 人。
3. **Haiku 毁掉了自己的经济。** 在民居格上建设施会拆掉 16 个住房，居民没地方住就陆续离开；居民没了，岗位、产出和新候选都没了。12 局里 9 局碰到。第二轮预演已经显示「住房 32→16」，6 局里仍有 5 局照建。

所以这次测不出「条令需要想到才用得出来」：瓶颈不在战斗上，Haiku 在当前信息量下也没有去试新组合。要评估条令，应该在战斗真正吃紧的地方测，比如从第 120 小时、打第 3–4 圈的中期存档开始，只让玩家决定条令和阵容；或者直接用战斗探针（`examples/doctrines.rs`）在第 3 圈以上的敌人身上比。

## 新玩家看不懂的地方

12 局反复出现的（括号里是提到的局数）。除了标明「仅文字版」的，网页上也是一样的问题：

1. **住房从哪来、设施为什么吃住房**（9）。没有任何地方说民居格才有住房、建设施会拆掉、没住处的人会走。
2. **新队员从哪来**（6）。候选来自街区人才，人才要有居民在岗才攒；局面里只有「队员 3/12」，看不出怎么增加。
3. **驻守和小队是同一批人**（6）。派驻守会把人从小队抽走，改编小队会把驻守撤下来，小队空了就不再探索，都没有提醒。
4. **反应图鉴的传闻对不上标签**（7）。「再厚的甲，泡久了也会锈穿」这种话，新玩家看不出是固守和侵蚀。
5. **接线员「共线」的范围**（6）。「所在街区边界格共用一处守军」读不懂。
6. **「每小时 +0.0」和资源在涨对不上**（6）。涨的是战利品和任务奖励，局面里只写了每小时产出（仅文字版：上一趟带回了什么没有列出来）。
7. **本轮成果怎么算**（2）。第二轮加了明细，还是不知道每项怎么涨。

仅文字版的问题（已修或无关）：`--json` 里格子要写编号（已改成也能写 G7）、上一趟没打仗时括号是空的（已改）、对照组里研究没有菜单但 `--json` 还能触发（两局误触，没有选到条令，不影响结论；已改成拒绝）。

## 之后

- 第 1–3 条值得先改：建设施的预演里写明「拆掉这格的住房，N 人会没地方住」；候选的来源在街区页写清楚；派驻守、改编小队时预演里列出小队人数的变化，空小队进「待你决定」。
- 条令评估改用中期存档或战斗探针（见上）。
- 再跑 LLM 试玩时用只开 Bash 的子代理：这次有 6 局 Haiku 乱调了会话管理工具（发消息、归档会话、排任务、订阅 PR），参数都不对，全部报错，没有产生任何效果。
- 文字版以后跟着功能一起改（见 `CLAUDE.md`）。

## 一周试玩打分（2026-11-27）

起因：爽点时间轴（`docs/balance-eval.md`“爽点时间轴”）要用 LLM 的反应来校准幅度分级，先拿现状做一次基线。一局 Haiku，种子 0，`AGENT_HOURS=168` 玩满一周，回访节奏模拟越来越少上线（计划第 1 天每 3 小时、第 2～3 天每 4 小时、第 4～7 天每 8 小时；实际第 1 天前 12 小时每 3 小时，之后每 4 小时，第 4～7 天多半是不做事的“离线”回访）。每次回访在 `--note` 里写“感受：惊喜/平淡/失望｜注意到的变化｜做了什么”，每个阶段结束时按八个维度打 1～5 分。

结果：本轮成果 297（管理 22，防御 265，探索 10），领地 6 格，最远第 1 环，守住来潮 199 次、失守 12 次，研究 4 次，废材 1514、零件 24、情报 86 没用掉。同种子的 `greedy`（每小时行动）一周成果 531，占 88 格，到第 5 环，研究 9 次。

| 维度（1～5，越高越好） | 第 1 天 | 第 2～3 天 | 第 4～7 天 |
|---|---|---|---|
| 成长感 | 2 | 2 | 2 |
| 新鲜感 | 3 | 3 | 2 |
| 目标感 | 2 | 2 | 1 |
| 回来有收获 | 3 | 2 | 1 |
| 决策趣味 | 2 | 3 | 2 |
| 省心 | 2 | 2 | 2 |
| 推进顺畅 | 2 | 1 | 1 |
| 看得懂 | 2 | 2 | 2 |

第 1 天的分是第 72 小时补打的，不是当场打的。

每次回访的感受（按回访时刻所在阶段计）：

| 阶段 | 惊喜 | 平淡 | 失望 |
|---|---|---|---|
| 第 1 天 | 2 | 2 | 3 |
| 第 2～3 天 | 3 | 3 | 6 |
| 第 4～7 天 | 0 | 15 | 9 |

记为“惊喜”的五次：第 3 小时第一批格子可占、第 12 小时废材开始有产出、第 32 小时第二座废材站有人上岗、第 44 小时规章自动招到特别队员（接线员）、第 56 小时小队出门一趟占下两格。研究三选一都记成“平淡”，选完“看不出效果”。第 4～7 天没有一次惊喜，最后几次回访写的是“只有守住来潮的计数在涨”“会考虑不再回来”。

读法：

- 和爽点时间轴的预期一致：能被感觉到的是扩张、经济起步和稀有招募，学说没有被感觉到；后半周没有新事件，回来有收获和推进顺畅掉到 1 分。
- 这局卡住的不是战斗：Haiku 只出过两次门，一直被“居民不上岗、收入 0”和“守格子的人不够”拖着（同 72 小时那两轮的第 2、3 条）。它试过 `set_priority`，看不出效果；废材堆到 1514 也不知道能拿来做什么。所以这一局的分数主要反映经济和人手说明不够，而不是数值节奏本身。
- 研究后菜单编号会变，Haiku 一次发多个编号时按错过一次（想派驻守，结果建了一座废材站）。
- 日志和打分：本地 scratchpad，不进仓库；之后改了节奏再跑同样的设置做对照。
