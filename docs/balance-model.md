# 数值数学模型

机器人回答“会发生什么”，数学模型回答“为什么会这样，要改成多少才对”。模型用公式把规则和内容数据串起来，直接算出结果，不跑对局；机器人跑出来的数字用来检验模型。两者对不上的地方要么是模型漏了机制，要么是机器人做了模型没想到的事，所以模型和实测的比值本身也是一项指标。评估框架见 `docs/balance-eval.md`，代码在 `engine/evalkit/src/model.rs`。

模型分两步：单位的速率（每回合打多少、奶多少、实际吃多少伤）用模拟量一次当系数，之后全部按公式组合。新职业、新敌人只要量一次系数，就能进模型。

```bash
cd engine
cargo run --release --example eval -- model                   # 量系数，检验战斗模型
cargo run --release --example eval -- pace --vs RUN.json      # 节奏模型，和机器人实测并排
cargo run --release --example eval -- pace --patch '{…}'      # 改数值前先算一遍
cargo run --release --example eval -- timeline 0 --hours 48   # 单局逐小时状态，查模型哪里不对
```

## 战斗：两道检查

每一波敌人最多打 `battle_max_rounds`（`balance.json`，15）回合，打不完算输。所以一场仗是两道独立的检查，两道都过才赢：

- **输出检查**：第 k 波的击杀回合 t_k = HP_k ÷ O_k，O_k = Σ atk_i · μ_职业 · m(def_k)。输出余量 = min_k 15 ÷ t_k。
- **生存检查**：第 k 波每回合打到小队身上的伤害 I_k = Σ atk_e · μ_敌人 · m(def_坦克) · φ_k · κ_小队，φ_k = (n+1)/2n 是敌人陆续倒下后平均还剩的比例。每回合净掉血 = max(0, I_k − H)，H 是小队每回合回血。生存余量 = 小队总血量 ÷ Σ_k 净掉血 · min(t_k, 15)。

模型强度取两道余量中较小的那个，大于 1 判赢。m(def) = 1 / (1 + def / 45.5)，和引擎的减伤公式相同。

系数（`eval model` 打印）：

- μ_职业：每点攻击每回合打出的伤害（未计目标防御），用 220 种三人组合在各环打赢的仗量出。例：突击 2.97、技师 1.68、射手 1.48、先锋 0.99、医疗兵 0.45。
- H_职业：每回合回血。医疗兵 29.9，玻璃园丁 15.2，工兵 6.6，其余为 0。
- μ_敌人：每个敌人单独打一个 150 血、零防御、不还手的假人，量出每点攻击每回合的伤害。
- κ_小队 = exp(β₀ + Σ β_职业)：实际吃到的伤害 ÷ 敌人系数预测的伤害，按职业做最小二乘，把挡伤、坚守、护盾折进去。玻璃园丁 −0.57、工兵 −0.38、医疗兵 −0.30（负数表示少吃伤）。

检验（模型从没见过这些仗）：

| | 模型 AUC | 模型准确率 | 模型 50% 点 | 旧指数 AUC | 旧指数 50% 点 |
|---|---|---|---|---|---|
| 实验室（带随机特质） | 0.977 | 0.91 | 1.30 | 0.965 | 0.38 |
| 实战（机器人真实小队，含学说和特质） | 0.961 | 0.80 | 0.73 | 0.927 | 0.10 |

刻度从差几倍变成差三成以内。实战里机器人小队输掉的仗 99% 是超时、人还站着，模型也判定输出检查在所有实战战斗里都是更紧的那道。实战 50% 点低于 1，是学说和特质的额外输出还没进系数，这部分由词条测价补（`docs/balance-eval.md`）。

## 节奏：每格耗时 × 格数

棋盘是方格，第 r 环有 8r 格（扣掉天险）。参考玩家 `greedy` 每 d 小时重新规划一次，所有小队打同一个最近的、能赢的格子：

- 每格要赢 w_r = ⌈(100 − 开局镇守度_r) ÷ 每胜镇守度⌉ 场。
- 一趟一格的出征耗时 T_r = 2 × 未占格路程 + 战斗回合数 × 每回合秒数，回合数取战斗模型的 Σ min(t_k, 15)。
- 每格耗时 h_r = max(d, d · ⌈w_r · T_r ÷ (小队数 · d · 3600)⌉) 小时，因为占下以后要等下一次规划才换目标。
- 到达时间：t₁ = h₁，t_{r+1} = t_r + (N_r − 1) · h_r + h_{r+1}。参考小队在某环的战斗余量 < 1 时，时钟停住（打不过）。

检验（`greedy`，20 个种子 p50）：

| | 第 2 环 | 第 3 环 | 第 4 环 |
|---|---|---|---|
| 现行规则：模型 / 实测 | 10.0 / 9.1 | 42.0 / 41.1 | 88 / 未到 |
| 一胜即占：模型 / 实测 | 9.0 / 8.1 | 25.0 / 24.1 | 47.5 / 46.1 |

模型和实测相差 10% 以内。由此能直接读出两条约束：

1. **吞吐量**：先清近环、每小时一格的打法下，到第 r 环至少要 Σ_{k<r} 8k ≈ 4r(r−1) 小时。到第 7 环要先占约 168 格，也就是大约一周，和设计稿“一轮约一周”一致。72 小时到第 7 环，要么每小时占两格以上（更多小队、一趟打多格），要么不清满整环。
2. **战斗墙**：参考小队（不带特质）在第 1～6 环的余量是 8.1 / 6.9 / 5.8 / 1.7 / 1.5 / 0.99。前三环余量很大，所以战斗卡不住；第 6 环才是墙。

### 血量（阶段 3 S4）

血量现在跨战斗保留，模型还没有接：两道检查仍按满血算，节奏模型里一格的耗时也没算“没血停下”的时间。2026-11-28 量的 `greedy` 3 个种子 72 小时：占格、到达各环的时间和不带血量时一致（第 4 环有一个种子早 1 小时），成果 ±1%，`medic.stopped_hp_h` 是 0——起始三人里有医护，战斗里回的血够多，路线上的仗几乎不掉血到停。掉血主要在守城：驻扎的人每 4 小时挨一次来潮，72 小时里倒下 21～40 次，用药线自动花掉 340～830 医疗，`surge_lost.all` 从 0.39/0.51/0.45 升到 0.42/0.51/0.51。所以要补的系数是“每场守城平均掉多少血”和“诊所的医疗产出能顶几个驻扎点”，等第一章的正式局（S7）有了诊所和驻扎的定数再量；现在模型和机器人的差在两成以内，原因是路线战斗没被血量卡住。

## 占格和建筑的价格（阶段 3 S6）

`engine/src/mech/cost.rs`，数在 `balance.json` 的 `costs`，固定地图可以在 `maps.json` 里用 `costs` 整组换掉。**现在只有教学关在涨价**：`balance.json` 的默认是中性的（`claim_base` 为空即占格不要钱，`claim_mult_bp`、`build_mult_bp` 都是 10000），随机地图的局和没有这条规则时一样；下面的数写在 `maps.json` 的教学关上。原因：按下面的数，随机地图第 16 次占格的价格已经超过废材仓库上限，机器人局卡死。正式局的数等教学关试玩以后再定。

- 占格：这一轮第 n 次占格（n 从 0 数，`CycleStats::tiles_claimed`，重新占回放弃的格子不算新的一次、也不涨价）花 `claim_base × claim_mult^n`。教学关 `claim_base` = 10 废材，`claim_mult` = 1.35：10、14、19、25、34、45、61、82、111、149……n = 14 时 668，n = 15 时 902 已经超过废材仓库上限 800；要是用在随机地图上，一轮最多占 15 格（不算开局就有的）。
- 建筑：同一种设施的第 n 座（n = 自己地上已经有几座这种设施）花它的基价 × `build_mult^n`，教学关 `build_mult` = 1.5。废材站：30、45、68、102；诊所：废材 45、68、102、152，零件 3、5、7、11。住房不要钱。
- 整数算：倍数是万分比，每乘一次向上取整到万分之一，最后向上取整到整数（`cost::grow`）。
- 节奏模型（上一节）还没有这一项（随机地图默认不涨价，所以现在不影响模型）：吞吐量那条现在是“每小时能占几格 = min(打下来的格数, 收入 ÷ 当前格价)”，格价指数涨，所以占格数大约是 log(收入 × 时间) / log 1.35 量级，几十格以后被价格卡死。没补进 `eval model`，S7 定正式局的数值时一起做。

## 反推：要让战斗当门槛

想让参考玩家在 τ_r 小时进第 r 环、且门槛来自战斗：

- 到 τ_r 时，参考小队对第 r 环的余量应该刚好在 1 附近（比如 1.0～1.3），之前小于 1。
- 输出检查是实战里的紧约束，所以第 r 环每波血量 ≈ 15 × O(τ_r) × m(def) ÷ 目标余量。O(t) 是参考小队在 t 时刻的输出。
- 吞吐量要快于战斗墙推进的速度：两道墙之间的格数 ÷ 间隔小时 ≤ 每小时能占的格数，否则卡人的是吞吐量，不是战斗。
- 因此 O(τ_7) ÷ O(τ_1) 就是一轮里玩家输出必须涨的倍数。现在第 6～48 小时，小队强度只涨了 10%。

## 爽点时间轴：研究时刻

局内成长靠研究学说（组织等级是周回成长，一轮之内不变），所以“第 n 次研究在什么时候”是成长节奏的骨架。爽点时间轴的定义和指标见 `docs/balance-eval.md`“爽点时间轴”。

- 第 k 次研究（从 0 数）花 `research_base + research_step · k` 情报，现在是 10 + 18k。前 n 次累计 C(n) = Σ_{k<n} (10 + 18k)。
- 情报一够就研究时，第 n 次的时刻 t_n = 累计情报收入第一次 ≥ C(n) 的时刻。收入曲线取机器人实测（`intel_in.h*`，含任务奖励和已花掉的），检查点之间线性插值。
- 指标 `payoff.model_ratio.research` = 各次研究 max(实测, 模型) ÷ 模型的中位数；`eval pace --vs RUN.json` 打印逐次对照，以及每环一周目标 τ_r 之前能做几次研究。

检验（`greedy`，8 个种子 × 168 小时，p50）：

| n | 本次花费 | 累计 | 模型（小时） | 实测（小时） | 实测 ÷ 模型 |
|---|---|---|---|---|---|
| 1 | 10 | 10 | 1.5 | 2.0 | 1.30 |
| 2 | 28 | 38 | 5.8 | 4.5 | 0.77 |
| 3 | 46 | 84 | 29.8 | 30.0 | 1.01 |
| 4 | 64 | 148 | 50.0 | 55.0 | 1.10 |
| 5 | 82 | 230 | 57.2 | 62.0 | 1.08 |
| 6 | 100 | 330 | 66.1 | 66.0 | 1.00 |

前两次的偏差来自机器人只在整点行动；第 3 次起都在一成以内，中位数 1.00：`greedy` 情报一够就研究，卡研究节奏的是收入，不是决策。

从模型读出的问题：

1. **情报收入第 72 小时以后停了**：累计收入第 6、12、24、48、72 小时是 39 / 48 / 71 / 125 / 398，到第 120 和 168 小时都只有 438。第 48～72 小时那一大段之后几乎没有进账，所以一周只有 6 次研究（8 个种子里 3 个做到第 7 次）。
2. **研究赶不上环**：按一周目标 τ_r，进第 2～7 环之前分别能做 2 / 2 / 3 / 6 / 6 / 6 次研究，后三环之间一次都不多。研究要当局内成长的主线，第 4 天以后的情报收入至少要跟上 C(n) 的二次增长。
3. **幅度量不出来**：现有内容下每次研究让参考小队模型强度变化的 m 都是 0。组织等级 1 能抽到的数值类学说只有 `plating`，它加的是生存，而输出检查才是紧约束；其余学说是效果类，模型看不到。前线格子在研究前就都能赢，所以由输转赢的格数也是 0。研究的幅度要另用模拟量（按固定遭遇表实际打，数赢了几场）。

## 还没有的部分

- **经济**：收入、库存、价格随时间的公式（库存小时、花钱间隔）。
- **防守**：边界格数随环增长，来潮次数和失守率的公式（一胜即占后，失守率从 0.42 升到 0.73）。
- **成长**：O(t) 怎么来。已定组织等级只决定一轮的起点（周回成长，局内不升级），局内成长靠研究学说；设施、装备算不算、各占多少还没定。
- **组合词条**：测价是单件开关，像“反应 + 电离”这种组合要成对测。
