# 提示词模板

评估里需要大模型做的事，都用这里的模板。仓库不放调用模型的代码：各模型由自己的 harness 驱动，harness 读模板、把变量换成实际内容、把回答交给人看。模板对任何模型都适用，不写某个模型专用的技巧。

| 模板 | 做什么 | 什么时候用 | 产出给谁 |
|---|---|---|---|
| [player.md](player.md) | 试玩玩家：按会话协议玩一局，每次回访记感受，阶段末打分 | 要 LLM 试玩时（`docs/eval-interface.md`） | 会话目录，`eval session` 重放算分 |
| [analyst.md](analyst.md) | 分析员：读评估报告，分清游戏问题和评估问题，写成可追加的条目 | 每次 `eval review` 之后 | 人审核后追加到 `docs/game-issues.md`，评估问题进待办 |
| [declare.md](declare.md) | 声明起草：新系统进来时，起草事件归类、指标、目标、机器人规则 | 加新系统、新事件、新命令时 | 人审核后改 `engine/eval/*.json` 和机器人 |

## 变量

- 写法是 `{{名字}}`，harness 原样替换成内容（文件内容、命令输出）。每个模板开头列出它的变量、来源和是否必填。
- 选填变量没有内容时替换成“（无）”，不要删掉所在的段落，模型据此知道缺了什么。
- 长内容（报告、diff）直接整段放进去，不要先让模型摘要再放。

## 规矩

- 模型只能看到模板里给它的东西：不让它读仓库、不让它上网。玩家尤其不能看源码和数值表，否则试玩结论就失真了。
- 分析员和声明起草的产出都是草案，人确认后才提交；模型不直接改仓库里的评估数据。
- 原始提示和回答由 harness 自己留档，便于事后追查某条结论是怎么来的。
- 改模板时，在本文件末尾记一行：日期、改了什么、为什么。旧的会话和报告不受影响。
