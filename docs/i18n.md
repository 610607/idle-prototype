# 文字与图像资源规范（i18n）

从 2026-11-27 起执行。目标：换语言只加文件，不改规则、内容数据和存档。

## 规则

1. **玩家看得到的文字只放在 `locales/<语言>/` 里。** 规则代码、内容数据（`engine/content/*.json`）、存档里都不放成品文字。
2. **代码按 key 取文字**，参数用名字填：引擎里 `t!("event.claimed", tile = label)`，网页和文字版用同一份 key。
3. **内容数据只放 id 和数字。** 名字、描述、传闻、名字池都在 `locales/<语言>/content.json`，key 是 `<类别>.<id>.<字段>`。
4. **图像只按 id 引用。** 图标在 `icons/pixel/<id>.txt`，内容里只写 icon id。图里不画字；需要给图配说明文字时，key 用 `icon.<id>`。
5. **存档里不存渲染好的句子。** 存 key 和参数（或 id），读档时按当前语言渲染：引擎里用 `txt!` 造一个 `i18n::Text` 存起来，显示时 `.render()`。内容名字存成引用（`i18n::name("doctrine", id)`），换语言后跟着变。生成的人名、街区名还是原样存（阶段 4）。
6. **新代码不准新增写死的文字。** `cargo test` 里的 `i18n` 测试会拦。

## 目录

| 文件 | 放什么 | key 例子 |
|---|---|---|
| `locales/zh-CN/content.json` | 内容数据的显示文字、名字池 | `trait.riot_veteran.name`、`names.given` |
| `locales/zh-CN/engine.json` | 引擎运行时、不进存档的文字：报错、待办、预演差异、成果明细、信任因素、属性名，以及几个客户端共用的词（地形、战果、前后排） | `err.no_op`、`view.pending.claim`、`delta.border` |
| `locales/zh-CN/events.json` | **存档会引用的** key：事件、队员出身、候选来源。改文字可以，改 key 名不行（旧存档会找不到），要换说法就加新 key | `event.claimed.city`、`origin.city`、`legacy.text` |
| `locales/zh-CN/battle.json` | 战报文字（战报不进存档） | |
| `locales/zh-CN/cli.json` | 文字版（`engine/src/textui.rs`）自己的界面文字，包括命令参考 | `cli.menu.build`、`cli.cmd.garrison` |
| `locales/zh-CN/web.json`（待建） | 网页界面文字 | |
| `locales/i18n-baseline.json` | 各源码文件里还剩多少写死的文字（棘轮基线） | |

格式：扁平 JSON 对象，key → 字符串；名字池这类是字符串数组。占位符 `{名字}`。默认语言 `zh-CN`；查不到时先退回默认语言，再退回 key 本身（界面上会直接看到 key，方便发现漏翻）。

## 引擎里怎么用

```rust
use idle_engine::{t, txt, i18n};
t!("stat.str.name")                                  // → "力量"，马上要显示的文字
t!("err.squad_full", n = 3)                          // "一队最多 {n} 人"
let e = txt!("event.claimed.city", tile = "G7", n = 7);   // 要存的文字：key + 参数
let r = txt!("event.research.done", name = i18n::name("doctrine", "react"));  // 参数也可以是 key
e.render()                                           // 显示时按当前语言渲染
idle_engine::i18n::set_locale("zh-CN")?;             // 引擎开始用之前设
```

- 马上显示、不存的（报错、view、预演、战报）用 `t!`；要存进状态的（事件、出身、来源）用 `txt!`，key 放 `events.json`。
- 预报里反复跑的计算（经济结算、不记日志的战斗）别造句子：存 key，到 view 里再 `t!`（例：`DistrictCalc.trust_factors` 存的是 `"trust.base"` 这样的 key）。不记日志的战斗整场跑在 `i18n::quiet` 里，查文字一律返回空串，所以战斗里不能拿文字做判断或存下来。

- 新语言：在 `engine/src/i18n.rs` 的 `BUNDLED` 里加一行，放齐同样的文件。`catalogs_match` 测试要求每种语言的 key 和 `zh-CN` 完全一致。
- 内容名字在内容第一次加载时按当前语言填进去（`content.rs` 的 `localize`），所以语言要在引擎启动前设。缺 key 会直接报错。

## 棘轮测试

`engine/tests/i18n.rs` 数每个源码文件里注释以外的汉字串（字符串、模板、JSX 文字都算；全角标点不算），和 `locales/i18n-baseline.json` 比：

- 某个文件变多 → 失败：把新文字挪进 `locales/`。
- 某个文件变少 → 也失败，提示你记下进度：`I18N_BLESS=1 cargo test --test i18n`。
- `engine/content/*.json` 里出现中文 → 失败。
- 代码里长得像 key 的字符串（`cli.menu.build`、`outcome.victory` 这种，开头是已有的前缀）在目录里查不到 → 失败，防止打错 key 以后界面上直接露出 key。

另有 `engine/examples/text_snapshot.rs`：跑三个种子，把玩家看得到的引擎文字（整份 view、战报、预演、拒绝原因、文字版、两轮之间、读档报错）写进一个文件。挪文字之前跑一次、之后再跑一次，同一种语言下两个文件必须逐字一致：

```bash
cargo run --release --example text_snapshot -- /tmp/before.txt   # 改之前
cargo run --release --example text_snapshot -- /tmp/after.txt    # 改之后
cmp /tmp/before.txt /tmp/after.txt
```

扫的范围：`engine/src/`（含文字版 `textui.rs`）、`engine/examples/agent_cli.rs`、`web/src/`（不含编好的 `pkg/`）。不扫：`engine/examples/` 里给开发者看的探针表格、冻结的 v0 原型 `src/`。
