# 设计 v2：重构、开发和测试计划（草稿）

2026-11-28。依据是 [总纲](design-v2-outline.md)、[引擎模型](design-v2-engine-model.md)、[开局和节奏](design-v2-opening.md)、[经营系统](design-v2-city.md)、[战斗系统](design-v2-combat.md)。每个阶段写清楚重构什么、开发什么、怎么测、过了什么算完成。

不写日期。规模用小、中、大表示，只用来比较各阶段。

## 进度和这次重排

- **阶段 0 已完成。阶段 1 停在现状，M1 不再跑**（2026-11-28 设计者决定）。已经做的改动留用：威胁跟分数走、仓库上限、路线墙前停下、硬打、占领预判、告急格不计分。没验证完的检查（多种子的平台、压分）并进后面的节点。
- 2026-11-28 重排成“按教学关的章节切”。原因：
  1. **第一局是教学关**：约一小时，固定地图，只玩一次，全部大系统逐个解锁、各做最浅的一层，以小核心收尾。第二局起是随机地图上的正式局，长度随局外解锁增长。
  2. **设计语法要成为引擎的类型**（见引擎模型）。这是一次大的重构，要在加新东西之前做。
  3. 每个阶段做好一两个系统，同时给教学关加一章、也加进正式局。每个节点都是一段能从头玩一遍的东西。

## 计划的三个前提

1. **在现有代码上分阶段改，不另起一套。** 每个阶段结束时游戏都能玩、评估都能跑。
2. **教学关网页和文字版一起做。** 教学关是坐着玩的，几秒一次反馈，文字版试不出手感。正式局里才有的东西仍是文字版先行，网页集中补。
3. **现有的系统先藏起来，再一章一章放出来。** 现在的游戏里研究、街区、来潮都已经有；阶段 3 把它们挂到解锁上。后面的阶段是把它们改造成新设计以后再放出来，不是从零做。

## 现状

- 引擎加评估工具约两万两千行。战斗核心 `mech/combat.rs` 约 2700 行，基本留用。
- “环”出现在 29 个文件里：地图生成、敌人强度、来潮、研究池、分数、特殊人物、评估指标。
- 评估目标 `engine/eval/goals.json` 全部按 168 小时和环写的，参考玩家是 `greedy`。
- 街区由地图给定（`District.tiles`），人口、信任、人才挂在街区上；格子的用途是“民居或设施”（`TileUse`），一格一个，定了不能挪。
- 客户端两个：文字版 `client/textui.rs`（约 2000 行）和网页。

## 每个阶段都要做的

来自项目约定，不在各阶段里重复写：

- 新命令、新信息、新预演同时进文字版；`textui::reach`、`textui::samples`、`cli.cmd.*` 补齐。
- 玩家看得到的文字进 `locales/`，数字进 `balance.json`。
- 新系统接进评估：指标登记到 `metrics.json`，机器人会用它，合格区间进目标文件，模型系数补上。
- 新词条跑 `eval price --bless`；新事件 key 在 `payoff_classes.json` 归类。
- 存档结构变了就把 `SAVE_VERSION` 加一，不写迁移。
- 试玩协议的观察或行动有不兼容的改动，把 `protocol` 加一并写进 `docs/eval-interface.md`。
- `cargo fmt`、`cargo test`；重编 WebAssembly 并提交 `pkg/`；`npx tsc --noEmit -p .` 要过。
- 阶段结束时更新 `docs/play-guide.md` 和对应的设计文档，把“还没实现”改成实际状态。
- 前面的章节不能退步：每个阶段结束时，教学关的标准走法仍然走得通，之前各章的时长和形状指标仍在区间内。
- 新想法先问它是哪个动词的实例（总纲的设计语法），能用现有规则表达的不加新规则；新效果用五段句式写（见 [引擎模型](design-v2-engine-model.md)），写不出来才加一种结果类型。
- 每个新系统登记一个解锁 id，写明它在教学关的哪一章、靠做到什么开放；更深的内容写明靠局外的什么解锁。

## 每个节点的通过标准

每个阶段的节点都由三部分组成，三部分都满足才算过：

1. **测试**：`cargo test` 全过，包括这个阶段新加的。
2. **评估**：这个阶段列出的指标落在区间内，新基线已经 `--bless`。
3. **试玩**：你自己把教学关从头玩到这个阶段新加的那一章，再开一局正式局玩到停住；加上一批 LLM 试玩（每批最多 3 个同时跑）。分工是：机器人管数值，算出来的指标管节奏的形状，LLM 管看不看得懂和打法分化，好不好玩由你判断。

节点没过时，先回到设计文档改设计，不带着问题进下一阶段。

## 阶段 0：准备（已完成）

不改玩法，只让后面的改动落在少数几个地方。

**重构**

- 给现在的版本打标签，旧基线 `engine/eval/baseline/` 另存一份，作为以后对照的 v1。
- **把“环”收到一个接口后面。** 所有读环的地方改成问同一处：这一格的进攻难度是多少、这一格的来潮强度是多少、研究池开到哪。阶段 1、6 换实现时只改这一处。
- **把分数收成一个函数。** 现在分数的各项权重已经在 `balance.json` 的 `score` 里；把计算集中到一处，输出各项明细。阶段 1 的威胁要读它。
- 地图生成里写死的波数、每波人数挪进 `balance.json`（原型 v2 的遗留问题）。

**评估工具**

- `eval run` 支持不定长：跑到给定的停止条件为止，不只按小时数。
- 目标文件支持“按平台算”的写法，和按小时的写法并存。旧目标保留。

**测试和节点 M0**

- `eval run greedy` 的读数和旧基线一致（同样的种子，逐项相等）。
- 文字快照前后逐字一致。
- 不需要试玩。

**结果（2026-11-28）**

- v1 是提交 `1770a5a`。`v1` 标签推不上去（代理拒绝推标签），只记在这里；旧基线另存在 `engine/eval/baseline-v1/`。
- M0 通过：`greedy` 3 个种子 × 72 小时，213 项指标逐项相等；文字快照逐字一致。
- 顺带发现：旧的分数里有随时间累加的项（守住的来潮、自给时长、最远深度），`greedy` 跑到 240 小时还在涨，没有平台。阶段 1 把分数换成“现在手里有的”。

## 阶段 1：威胁跟分数走，打不过就停（停在现状）

已经合进主干：威胁跟统计分数走、仓库上限、路线墙前停下、手动硬打、占领预判、告急格不计分。**M1 不再跑，停在现状**；下面的节点留作记录，没验证完的检查并进阶段 5 和阶段 6 的节点。

**开发**

- **统计分数**：建好的、练好的按高权重，库存按低权重。权重进 `balance.json`。
- **来潮强度读统计分数**，取代按环查的来潮表。
- **仓库上限**：先用固定数字，每种资源分别计。
- **路线打不过就停**：出发前预演，没把握的格子不打，队伍转去巡逻。巡逻的收益要低于推进。
- **手动硬打**：一条命令，输了全队撤回休整。
- 文字版显示：统计分数和明细、威胁读数、每支队伍停在哪、为什么停。

**暂时不动**

- 进攻难度仍然按环（阶段 6 换成异界源）。
- 军械面板留着（阶段 5 并进街区档位）。

**评估工具**

- 新指标：平台分数、到平台的时间、放手不管以后的损失、每样东西招多少威胁（`eval price` 加一列）。
- 新机器人：压分玩家（一直不涨分）。
- 新目标：平台存在；收敛；一直压分不占便宜。先压后放的藏锋打法是正当的，到阶段 6 另设人格。

**测试**

- **收敛检验**（进 `cargo test`，用小规模）：若干种子，在几个时间点取局面，之后不下任何命令再跑一段时间，损失不超过上限，局面不再变化。
- 仓库到上限后，统计分数和威胁都停住。
- 预演说能赢的格子，实际一定赢（战斗是确定的，这条应该恒成立）。

**节点 M1**

| 检查 | 标准 |
|---|---|
| 平台 | `greedy` 的分数在各种子上都会停住，不会一直涨，也不会涨到一半崩掉 |
| 收敛 | 放手不管，损失不超过上限 |
| 压分 | 压分玩家的最终分数低于 `greedy` |
| 挂机进攻 | 挂机期间进攻没有任何损失（阶段 3 起改成：损失只有药，且不低于保留线） |
| 试玩 | 离开一两天回来，局面没有变坏；能看懂队伍为什么停 |

**这个节点可能推翻什么**：如果怎么调权重都没有平台（一直涨或者一碰就崩），“威胁跟分数走”这条要回到设计上重谈。所以它排第一。

**M1 结果（2026-11-28，未全部做完，按要求先停在这里）**

| 检查 | 结果 |
|---|---|
| 平台 | 过（旧规则下 2 个种子）：`greedy` 在第 180、191 小时停住，平台分数 2474、2649，没有中途回落（`score.drop` 0）。告急格不计分以后没有重跑 |
| 收敛 | 改了以后待测。旧规则下放手 48 小时，路线一仗不输、一格不丢，但平均有 6.5 格（第 24 小时起）和 24.5 格（第 72 小时起）掉进告急。于是改成告急格不计入分数和威胁，探针改记新掉告急的比例（`handsoff.alerted`）和第二天的失守（`handsoff.day2_lost`）；`cargo test` 的收敛检验加了“最后一天不再新掉告急”，已经通过。`hands_off` 目标里新掉告急的上限还没定 |
| 压分 | 待测：压分玩家的运行中途停了 |
| 挂机进攻 | 过：放手不管的两天里路线没有打输过（`handsoff.trip_lost` 0），预演能赢的格子实际都赢（`cargo test`） |
| 试玩 | 第二轮基本过：离开一天回来不再变坏；队伍为什么停，“没收益只巡逻”看得懂，“前面打不过”有一位没看懂，已改说明，还没再试 |

- **第一轮试玩没过**（三位 Haiku，每 24 小时回来一次，`engine/eval/sessions/2026-11-28-m1/`）：三局都是刚占下、没人驻扎的第 1 圈格子守不住来潮，威胁为 0 也守不住，可是占领那一刻看不到这个后果。三局失守 12、16、25 次，终局告急 0、4、4 格，8 次回访里记“失望”的有 4、4、5 次。所以问题不在“威胁跟分数走”，在“坏事要能提前看见”（总纲原则 5）。
- **改了什么**：可占领那一行写占下后守不守得住；要人驻扎时写出谁能守住（先挑闲着的，没有才从小队里挑），菜单和格子面板多一项“占领并派某某驻扎”。告急格不计入分数和威胁。仓库上限显示出来，满了标出。巡逻和停下的说明写清楚该怎么办。
- **第二轮试玩**（同样三人、同样种子，`engine/eval/sessions/2026-11-28-m1b/`）：失守 0、0、4 次，终局告急 0、0、0 格，记“失望”的 0、2、2 次。唯一的失守是扩张征服用普通“占领”占了一格要人驻扎的地，没派人，第二天只好放弃。
- **没做的**：`greedy` 8 个种子的平台运行和压分玩家的运行中途停了，新基线没有 `--bless`，其余 5 个人格的基线还是旧规则下的；按计划，你自己用文字版玩一次也还没做。

## 阶段 2：引擎重构

把现有的游戏搬到 [引擎模型](design-v2-engine-model.md) 的类型上。**玩法不变，读数和重构前的基线逐项相等。** 基线是重构开始前主干上的读数，原样存下，不问好坏：六个参考玩家各 3 个种子、72 小时，存在 `engine/eval/baseline-pre-refactor/`。开始重构前如果主干又有改动，重跑一遍。 全项目最大的一次重构，分三步，每步结束都能跑、都对得上基线。

**2a 实体、属性和状态**

- 队员、建筑、装备、条令、小队、格子统一成实体：身份、标签、属性表、状态、声明的接口。
- 属性和状态分开：属性随时重算、不存档；状态存档。
- 接口在数据层声明，每种带自己的数据块。守城建筑改成正式声明“可出战”，去掉特例。
- 资源和居民保持是数量。

**2b 容器**

- 容器分有位置和没有位置两种。棋盘、小队、装备槽、条令槽是前者；街区、阵营是后者。
- 库存、替补席也是容器。
- 建筑从“格子的用途”改成放在格子槽里的实体，可以取下、进库存。玩法上暂时仍不能挪。
- 归属改成阵营容器。

**2c 效果句式和战斗**

- 效果统一成五段：时机、条件、对象、结果、代价。现有战斗数据里的条件、目标、触发三种枚举是起点，推广到全游戏。
- 现有的学说、特质、装备词条、设施效果、街区特色改用句式表达。
- 标签并成一套词汇、一张反应表。
- 战斗改成“两个有位置的容器进了战场”；专用代码只留回合调度，回合里的事走句式。行动点和被动点是代价。
- 每种结果都能无副作用地模拟，预演统一成一个入口。

**探针**

- 放两件只在测试里出现的内容：一个同时可出战、可放置的实体，一条定期交换两个实体位置的效果。测试一直验证引擎确实通用。玩家看不到。

**文档和约定**

- `docs/architecture.md` 按新的类型重写；项目约定里“引擎层尽量不动”改掉。
- `tests/layers.rs` 跟着调整。

**测试和节点 M2**

| 检查 | 标准 |
|---|---|
| 读数 | 六个参考玩家的指标和 `baseline-pre-refactor` 逐项相等；2a、2b、2c 每步都查 |
| 文字 | 文字快照前后逐字一致 |
| 预演 | 预演和实际结果一致，进攻和守城用同一个入口 |
| 探针 | 探针实体能在格子和队伍之间移动；交换效果按时触发，告急格和战斗中的不换 |
| 没有特例 | 机制层里不再有按“队员还是建筑”分支的代码（守城建筑、装备、学说各查一遍） |
| 速度 | 评估跑一局的时间不比重构前慢太多（先定一个倍数） |

不需要试玩。

**这个节点可能推翻什么**：如果某个现有机制怎么也写不成句式，先加结果类型；加了很多还不够，说明五段句式不够用，回到引擎模型重谈。如果读数对不上基线又查不出原因，退一步：战斗内部先不搬（2c 的后半），其余照做。

## 阶段 3：教学关第一章和最小的轮回闭环

第一个你能从头玩到尾的东西：教学关的第一章（约 15 分钟），一个临时的收尾，收束，开一局正式局。依据是 [开局和节奏](design-v2-opening.md)。

**重构**

- **时钟按秒走。** 教学关全程用细刻度。先定方案再动 `mech/sim.rs`。
- **固定地图**：教学关的地图、敌人、掉落写在内容数据里，不走地图生成，不用随机种子。
- **解锁登记表**（数据层）：每个系统、每个部门、每类内容一个解锁 id，写明靠什么开放。机制层和两个客户端都按它决定显示什么、能做什么。
- 现有的研究、街区、军械、来潮、条令、特别队员全部挂到解锁上，这一阶段不出现。
- 评估支持连跑多局；统计和爽点时间轴支持秒级。试玩协议改成一局一次连续会话，`protocol` 加一。

**教学关第一章里有什么**

- 固定地图，开始只露出家门口的几格。
- **走**：亲手派人去打隔壁的格子，几秒出结果。
- **摆**：占下的格子上放建筑，产出开始跳。邻格关系只做最简单的一两种。
- **状态保留**：队员不自动回血；医疗资源；治疗的消耗按缺的血量指数增长；倒下回家读条；全灭传回、丢一部分战利品。
- **头两层自动化**：路线自己跑（调度部门成立）；按线自动用药。自动之后保留手动派遣。
- **提前露出**：下一样东西看得见、买不起、显示还差多少。
- **成本按倍数涨**：占格和建筑。
- **临时的收尾**：一场比平常难一点的战斗，打下来就可以收束。阶段 6 换成正式的小核心。

**最小的轮回**

- 结算分数；带走一名队员。
- 局外的解锁页：做到了什么、开了什么。
- **正式局的壳**：随机地图，只有这一章的系统；开头是几分钟的压缩版回顾，带来的人让它明显变快；分数停住以后玩家自己决定收束。

**评估工具**

- 形状指标登记到 `metrics.json`：开局密度、相邻里程碑的间隔比、每种手动操作被自动化前的重复次数、一局多长、到平台的时刻。
- `goals.json` 改成按局写，时间用对数刻度。旧的 168 小时目标留作长局的参考，不再是默认。
- **标准走法**：一条写死的脚本把教学关从头走到尾，记下每一步的时刻，进 `cargo test`。之后每个阶段往后接。
- 机器人能走完教学关并收束、开正式局。
- LLM 试玩：连续玩完教学关；结束时问“还想接着玩吗，为什么”；用比较代替打分。
- 记录你自己的游玩，用来校准形状指标。

**测试**

- 标准走法走得通，每一步的时刻在规定范围内。
- 每个按钮出现时，离买得起不超过规定的倍数。
- 没解锁的系统，命令被拒绝，文字版和网页都不显示。
- 状态守恒：不治疗时，上一场结束的血量等于下一场开始的。
- 放手不管：药停在保留线，队伍停住，局面不再变。

**节点 M3**

| 检查 | 标准（数字是初步的） |
|---|---|
| 第一个结果 | 10 秒内 |
| 头 1 分钟 | 至少 3 样新东西 |
| 第一层自动化 | 5 分钟内 |
| 头 15 分钟 | 至少 10 样新东西 |
| 间隔比 | 相邻里程碑的间隔比在 1.3 到 2 之间 |
| 这一章多长 | 标准走法 10 到 20 分钟 |
| 药 | 有一段时间是瓶颈，但不是从头卡到尾 |
| 正式局开头 | 到教学关同一进度的时间明显更短，但不是零 |
| 试玩 | 你自己一口气玩完这一章，中途不想关；结束时想接着玩 |

**这个节点可能推翻什么**：按这一章的密度推算，一小时装不下全部系统。那就把教学关放长，或者把一部分系统挪出教学关、改成局外解锁。如果医疗只是多了一个要盯的数，就把自动用药做得更省心，或者挪到后面的章节。

## 阶段 4：第二章

教学关加到约 30 分钟。主题是“碰”：标签、反应和构筑。

**开发**

- **标签和反应**开放。队员、装备、建筑带的是同一套标签。
- **标签跨战斗保留**：先打哪格后打哪格因此有讲究。
- **第二支队伍和出战名额**：总名额由玩家分；一队最多六人，前后排各三。
- **研究**：一种研究点；先只开一副牌，三选一；价格走阶梯；不在时待选的卡等着。
- **第三层自动化**：研究队列。
- **条令**按队装备，带实例和品质（先两档）。
- 反应图鉴，显示空位。
- 教学关第二章的编排：第一名带标签的队员、第一次反应、第一张研究牌各安排在哪。
- 正式局里这些系统给完整的深度。

**评估工具**

- 发现的节奏：新标签、新反应各在什么时候出现；不同种子是否不一样。
- 机器人学会：分名额、选牌、排路线的先后。
- 条令测价按档算。

**节点 M4**

| 检查 | 标准 |
|---|---|
| 这一章多长 | 标准走法 10 到 20 分钟 |
| 发现 | 正式局里至少若干次第一次触发的反应，分布在前中后段 |
| 顺序有用 | 至少有一类路线，调换两格的先后会改变结果 |
| 集中和分散 | 两种分名额的办法分数都过得去 |
| 前面不退步 | 第一章的各项指标仍在区间内 |
| 试玩 | 有“这个组合居然能这样用”的时刻 |

## 阶段 5：第三章

教学关加到约 45 分钟。主题是城市。教学关里只圈一个街区、守一次来潮；完整的布局在正式局里。工程量大，分三步，每步都能跑。依据是 [经营系统](design-v2-city.md)。

**5a 自由重摆和玩家圈街区**

- 命令：挪建筑、交换两格的建筑、圈街区、解散街区。告急的格子不能挪。失守时建筑退回库存。
- 街区数量和大小的上限（固定数字）。重划时信任跟着居民走。
- 地图生成不再给街区。

**5b 类别、属性和联动**

- 建筑归到六个类别，补缺的建筑。类别就是标签。
- 街区属性写成挂在街区上的效果：成员标签满多少，开放什么。进度显示。
- 格子的地形和“曾经的用途”是格子自己带的标签。
- 邻格联动（含少量负面）。
- 属性决定候选的职业，档位决定品质；双属性出混合职业。
- 军械面板取消，数值并进工坊和守备的档位。
- 路线经过自己的建筑时发生什么，每类一种。

**5c 来潮和守城**

- **来潮开放**，强度读统计分数（阶段 1 的成果）。来潮是敌人的路线，和进攻共用预演和战报。
- 每个街区一个守备阵型；守城建筑、民兵、驻扎队员排进去。
- 第四、五层自动化：岗位自动填；自动摆放加钉子。
- 离开再回来：正式局从这里开始需要离线结算。

**评估工具**

- 机器人摆城市用自动摆放；另做一个搜索布局的办法，量手动能比自动好多少。
- 街区的分布、六个类别的占比、资源流会不会卡死。
- `builder` 人格重写规则。
- 收敛检验接回来：放手不管，损失不超过上限。

**测试**

- 任意重摆、重划以后，人口、信任、库存的总量守恒。
- 告急格上的建筑挪不动；失守后建筑在库存里。
- 自动摆放的结果总是合法的。
- 守城的结果和预演一致。

**节点 M5**

| 检查 | 标准 |
|---|---|
| 这一章多长 | 标准走法 10 到 20 分钟 |
| 正式局多长 | 参考玩家几小时到半天到平台 |
| 布局深度 | 搜索出的布局比自动摆放明显好；只好一点说明联动太弱 |
| 补给线 | 把建筑摆在出征路上的布局，比不考虑路线的明显好 |
| 类别 | 没有哪一类永远不建，也没有哪一类占掉大半 |
| 平台和收敛 | 正式局的分数在各种子上都会停住；放手不管，损失不超过上限（阶段 1 没验证完的检查） |
| 前面不退步 | 前两章的指标仍在区间内 |
| 试玩 | 重摆城市是有意思的，不是负担；离开几小时回来，局面没有变坏 |

## 阶段 6：第四章，教学关完整

教学关加到约一小时。主题是墙。教学关里只有一族的第一层和一个小核心；多族、深层在正式局里。依据是 [战斗系统](design-v2-combat.md)。

**开发**

- 进攻难度从“第几环”换成“离哪个异界源多远、源多强”。地图生成放置异界源。
- **先做两族**，每族三层：惯用标签、抗性和弱点、一条行为规则。行为规则用效果句式写。
- **战报诊断**：输在哪一步，谁被什么打死，哪个标签没人处理；给出战术规则的修改建议。
- **图鉴**逐层揭开。**碎片**和反制。
- **核心**：每个源一个首领战，带一条独有的规则；打下来可以占领，这一族在来潮里的压力下降。
- **教学关的收尾换成小核心**：打下来，收束，进轮回。阶段 3 的临时收尾去掉。
- 研究开第二副牌（战斗和城市分开）。
- 现有的二十种敌人、二十八条学说归到两族和通用池里。

**评估工具**

- 每族的打法数：搜索队伍构成，数能赢的有几种不同的构成。
- 墙的位置、停多久、用哪一档手段过的。默认规则和搜索出的规则的差距。
- `tactician` 人格用上诊断、按族换条令。
- 压分玩家和藏锋人格。

**节点 M6**

| 检查 | 标准 |
|---|---|
| 教学关多长 | 标准走法 40 到 70 分钟；熟练的走法半小时左右 |
| 教学关的密度 | 平均四五分钟一样新东西；没有超过规定时长的空档 |
| 打法数 | 每族在近处那一层，至少三种不同构成的队伍能过 |
| 墙 | 一局里出现多道墙；没有只靠等就过去的墙 |
| 默认规则 | 只用默认规则的机器人能过标准难度下所有的墙 |
| 高潮 | 教学关以小核心收尾；参考玩家在正式局里至少打下一个核心 |
| 压分 | 一直压着分数不涨的玩家，最终分数低于参考玩家（阶段 1 没验证完的检查） |
| 前面不退步 | 前三章的指标仍在区间内 |
| 试玩 | 你自己把教学关从头玩到收束，一小时里不想关；正式局里撞墙时知道该琢磨什么，过墙时觉得是自己想出来的 |

**这个节点可能推翻什么**：现有的战斗做不出“三种打法”，要么加标签和反应，要么调整三层的设计。

## 阶段 7：正式局的深度一

主题是零件的两条来路。这一阶段起的东西不进教学关，靠局外解锁。

**开发**

- **仿制**：拆解得图纸，工坊造同款；图纸可以带走。
- **品质**三档和合成，装备、条令、政策统一处理。
- **政策**：信任开槽，按属性给，街区级。
- **建筑升级**三级，第三级二选一。加工链：工坊吃废材出零件；仓库上限由市集建筑给。
- **现场复活**的技能和道具；多次现场复活长出词条。
- 复活时间可以靠科技和建筑缩短。
- 加第三族，带自己的一种标签和几条新反应。
- “变”的其他实例从战斗和经营文档文末的例子里挑，按语法检验后再加。

**评估工具**

- 后勤打法各设一个策略：常规、残血、复活、轮换。
- 仿制和掉落各供了多少装备；四种资源和药的两条来路各用了多少。
- `builder` 和 `tactician` 跑同样的局。

**节点 M7**

| 检查 | 标准 |
|---|---|
| 正式局多长 | 解锁了这些以后，参考玩家一两天到平台 |
| 两侧过墙 | `builder` 和 `tactician` 都能过每道墙，总分差距在区间内 |
| 后勤打法 | 常规、残血、复活三种打法的最终分数都在一个区间内；一直压着不放的低于先压后放的 |
| 两条来路 | 每种资源和装备，城市和战斗两条路都有人格在用 |
| 前面不退步 | 教学关的指标仍在区间内 |
| 试玩 | 收菜加规划的节奏出现了：每天上线几次，隔一两天琢磨一次 |

---

## 阶段 8：正式局的深度二

正式局逐步到一周。主题是收菜有事做。

**开发**

- **刷新点**：事件、战斗、物资，只刷在看得见的范围；不过期，数量有上限，可以手动删除。
- **派遣**替补去处理刷新点；地盘内的战斗是**切磋**。
- **三态迷雾**：未知、有迹象、看清。
- **特殊异界格**：种类每局随机，带固定特殊队员的招募。现有的三名特别队员改成从这里来。
- **异界特殊建筑**；**障碍**和清障科技。
- 长局用粗的时间刻度和离线结算；细刻度到粗刻度怎么过渡在这里定。

**评估工具**

- 机器人有处理刷新点的规则；量每次回访能处理几个、收益占多少。
- 刷新点攒到上限以后局面不变（并进收敛检验）。
- LLM 试玩用前密后疏的日程。

**节点 M8**

| 检查 | 标准 |
|---|---|
| 收菜 | 几分钟的回访里有两三件可做的事，不需要深决策 |
| 不错过 | 离开很久回来，刷新点停在上限，没有损失 |
| 迹象 | 探索方向和迹象相关，不是盲走 |
| 前面不退步 | 教学关的指标仍在区间内 |
| 试玩 | 每天上线几次，不觉得是在打卡 |

## 阶段 9：局外的后段

**开发**

- **难度条件**：开局勾选，可以叠加；分数乘系数，同榜记录勾了哪些。
- **总部部门的升级**：部门的成立已经在教学关里随各章开放；这里做升级、一局升不满、解锁过的种类跨局保留。
- **转化异界格**：打下过核心的族才能转。
- **颠覆规则的内容**：跨接口的实体（能当建筑的特殊队员）、交换效果。阶段 2 的探针在这里变成真的内容。一次只放一个。
- 第六层自动化。
- 带走的名额和挑选界面补全；特殊队员名额另算。

**评估工具**

- 每个难度条件实际让分数掉多少，和系数对不对得上。
- 带走的东西让下一局快多少。
- 部门的升级顺序是否因人格而不同。

**节点 M9**

| 检查 | 标准 |
|---|---|
| 系数 | 每个难度条件的系数略高于它实际造成的分数损失 |
| 逐局上升 | 机器人连跑多局，乘了系数的分数逐局上升 |
| 例外 | 每件颠覆规则的内容都带出至少一种原来没有的打法 |
| 试玩 | 多局以后仍有没见过的东西；挑什么带走是个值得想的问题 |

## 风险

| 风险 | 在哪暴露 | 怎么办 |
|---|---|---|
| 威胁跟分数走调不出稳定的平台 | M1 | 回到设计，重谈威胁的算法 |
| 重构后读数对不上基线，或者句式装不下现有机制 | M2 | 分三步、每步对基线；退路是战斗内部先不搬 |
| 抽象长期只有常规内容在用，悄悄退化成特例 | 阶段 2 以后 | 探针内容一直在测试里 |
| 一小时装不下全部系统的最浅一层 | M3 起，每章都看 | 放长教学关，或把一部分系统挪成局外解锁 |
| 时钟按秒走牵连太广，评估变慢 | 阶段 3 | 先定方案再动；长局仍用粗刻度 |
| 教学关信息太密，记不住 | M4 到 M6 试玩 | 每样只教最浅的一层；正式局开头的回顾再提一遍 |
| 教学关和正式局脱节：教的和实际玩的不是一回事 | M5、M6 | 两边用同一套系统和数据，教学关只是固定了地图和顺序 |
| 前面的章节被后面加的东西改坏 | 每个阶段 | 标准走法在 `cargo test` 里；“前面不退步”是每个节点的检查 |
| 布局只有一个最优解，或者自动摆放就够好 | M5 | 加负面联动和地块差异；仍然不行就降低城市的分量 |
| 现有战斗做不出每族三种打法 | M6 | 加标签和反应，或者简化三层 |
| 机器人跟不上新系统，评估失真 | 每个阶段 | 机器人规则和功能一起做，`commands.never` 不能有新命令 |
