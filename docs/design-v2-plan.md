# 设计 v2：重构、开发和测试计划（草稿）

2026-11-28。只是计划，还没有动手。把 [总纲](design-v2-outline.md)、[经营系统](design-v2-city.md)、[战斗系统](design-v2-combat.md) 拆成有先后的阶段，每个阶段写清楚重构什么、开发什么、怎么测、过了什么算完成。

不写日期。规模用小、中、大表示，只用来比较各阶段。

## 待你确认的三个前提

计划按下面三条写的，哪条不同意，对应的地方要改：

1. **文字版先行，网页后跟。** 每个阶段只做引擎、文字版、评估工具和文字资源；网页只保证能编译、能打开，新东西不显示。网页在两个节点集中补（见“网页”一节）。
2. **战斗（阶段 2）排在城市（阶段 3）前面。** 两者可以对调，代价见阶段 3 的说明。
3. **在现有代码上分阶段改，不另起一套。** 战斗核心、时钟、存档、随机留用；每个阶段结束时游戏都能玩、评估都能跑。

## 现状

- 引擎加评估工具约两万两千行。战斗核心 `mech/combat.rs` 约 2700 行，基本留用。
- “环”出现在 29 个文件里：地图生成、敌人强度、来潮、研究池、分数、特殊人物、评估指标。
- 评估目标 `engine/eval/goals.json` 全部按 168 小时和环写的，参考玩家是 `greedy`。
- 街区由地图给定（`District.tiles`），人口、信任、人才挂在街区上；格子的用途是“民居或设施”（`TileUse`），一格一个，定了不能挪。
- 客户端两个：文字版 `client/textui.rs`（约 2000 行）和网页。

## 每个阶段都要做的

来自项目约定，不在各阶段里重复写：

- 新命令、新信息、新预演同时进文字版；`textui::reach`、`textui::samples`、`cli.cmd.*` 补齐。
- 玩家看得到的文字进 `locales/`，数字进 `balance.json`。
- 新系统接进评估：指标登记到 `metrics.json`，机器人会用它，合格区间进目标文件，模型系数补上。
- 新词条跑 `eval price --bless`；新事件 key 在 `payoff_classes.json` 归类。
- 存档结构变了就把 `SAVE_VERSION` 加一，不写迁移。
- 试玩协议的观察或行动有不兼容的改动，把 `protocol` 加一并写进 `docs/eval-interface.md`。
- `cargo fmt`、`cargo test`；重编 WebAssembly 并提交 `pkg/`；`npx tsc --noEmit -p .` 要过。
- 阶段结束时更新 `docs/play-guide.md` 和对应的设计文档，把“还没实现”改成实际状态。

## 每个节点的通过标准

每个阶段的节点都由三部分组成，三部分都满足才算过：

1. **测试**：`cargo test` 全过，包括这个阶段新加的。
2. **评估**：这个阶段列出的指标落在区间内，新基线已经 `--bless`。
3. **试玩**：你自己用文字版玩过，加上一批 LLM 试玩（每批最多 3 个同时跑）。读数只能说明数值没坏，循环好不好玩要人来判断。

节点没过时，先回到设计文档改设计，不带着问题进下一阶段。

## 阶段 0：准备

不改玩法，只让后面的改动落在少数几个地方。

**重构**

- 给现在的版本打标签，旧基线 `engine/eval/baseline/` 另存一份，作为以后对照的 v1。
- **把“环”收到一个接口后面。** 所有读环的地方改成问同一处：这一格的进攻难度是多少、这一格的来潮强度是多少、研究池开到哪。阶段 1、2 换实现时只改这一处。
- **把分数收成一个函数。** 现在分数的各项权重已经在 `balance.json` 的 `score` 里；把计算集中到一处，输出各项明细。阶段 1 的威胁要读它。
- 地图生成里写死的波数、每波人数挪进 `balance.json`（原型 v2 的遗留问题）。

**评估工具**

- `eval run` 支持不定长：跑到给定的停止条件为止，不只按小时数。
- 目标文件支持“按平台算”的写法，和按小时的写法并存。旧目标保留。

**测试和节点 M0**

- `eval run greedy` 的读数和旧基线一致（同样的种子，逐项相等）。
- 文字快照前后逐字一致。
- 不需要试玩。

## 阶段 1：威胁跟分数走，打不过就停

**开发**

- **统计分数**：建好的、练好的按高权重，库存按低权重。权重进 `balance.json`。
- **来潮强度读统计分数**，取代按环查的来潮表。
- **仓库上限**：先用固定数字，每种资源分别计。
- **路线打不过就停**：出发前预演，没把握的格子不打，队伍转去巡逻。巡逻的收益要低于推进。
- **手动硬打**：一条命令，输了全队撤回休整。
- 文字版显示：统计分数和明细、威胁读数、每支队伍停在哪、为什么停。

**暂时不动**

- 进攻难度仍然按环（阶段 2 换成异界源）。
- 军械面板留着（阶段 3 并进街区档位）。

**评估工具**

- 新指标：平台分数、到平台的时间、放手不管以后的损失、每样东西招多少威胁（`eval price` 加一列）。
- 新机器人：压分玩家（故意不涨分）。
- 新目标：平台存在；收敛；压分不占便宜。

**测试**

- **收敛检验**（进 `cargo test`，用小规模）：若干种子，在几个时间点取局面，之后不下任何命令再跑一段时间，损失不超过上限，局面不再变化。
- 仓库到上限后，统计分数和威胁都停住。
- 预演说能赢的格子，实际一定赢（战斗是确定的，这条应该恒成立）。

**节点 M1**

| 检查 | 标准 |
|---|---|
| 平台 | `greedy` 的分数在各种子上都会停住，不会一直涨，也不会涨到一半崩掉 |
| 收敛 | 放手不管，损失不超过上限 |
| 压分 | 压分玩家的最终分数低于 `greedy` |
| 挂机进攻 | 挂机期间进攻没有任何损失 |
| 试玩 | 离开一两天回来，局面没有变坏；能看懂队伍为什么停 |

**这个节点可能推翻什么**：如果怎么调权重都没有平台（一直涨或者一碰就崩），“威胁跟分数走”这条要回到设计上重谈。所以它排第一。

## 阶段 2：敌人分族

**重构**

- 进攻难度的接口换实现：从“第几环”换成“离哪个异界源多远、源多强”。
- 地图生成放置异界源；格子记下属于哪一族、带到第几层。
- `Squad` 加学说槽；学说从全局生效改成按队装备。
- 评估里按环的指标（进第几环的时间、前线胜率）换成按源、按层的。

**开发**

- **先做两族**，用现有的标签。现有的两种世界修正（偏震荡、偏侵蚀）是现成的起点。每族三层：惯用标签、抗性和弱点、一条行为规则。
- **行为规则**做成数据层的效果种类，机制层读它；能用现有效果种类表达的就不加新的。
- **出战总名额**（先用固定数字）由玩家分到各队；一队最多六人。
- **战报诊断**：输在哪一步，谁被什么打死，哪个标签没人处理；给出战术规则的修改建议。
- **图鉴**：遇到过的族，逐层揭开。
- 现有的二十种敌人、二十八条学说归到两族和通用池里。

**评估工具**

- 每族的打法数：枚举或搜索队伍构成，数能赢的有几种不同的构成。
- 墙的位置、停多久、用五档手段里的哪一档过的。
- 默认规则和搜索出的规则的差距。
- 机器人学会：分名额、按族换学说、看诊断调队。`tactician` 人格用上这些。

**测试**

- 每族每层至少有一支测试队能赢、一支不能赢（防止某一层其实不起作用）。
- 两族混编的格子，敌人构成符合数据。
- 六人队、三人队的战斗都确定。

**节点 M2**

| 检查 | 标准 |
|---|---|
| 打法数 | 每族在近处那一层，至少三种不同构成的队伍能过 |
| 墙 | 一局里出现多道墙；没有只靠等就过去的墙 |
| 默认规则 | 只用默认规则的机器人能过标准难度下所有的墙 |
| 集中和分散 | 两种分名额的办法分数都过得去 |
| 试玩 | 撞墙时知道该琢磨什么；过墙时觉得是自己想出来的 |

**这个节点可能推翻什么**：如果现有的战斗引擎做不出“三种打法”，要么加标签和反应的数量，要么调整三层的设计。

## 阶段 3：城市背包

工程量最大的一块，内部分四步，每步结束都能跑。

**3a 重构：人口和建筑脱离格子**

- 建筑从“格子的用途”改成物品：有库存，放在格子上，可以取下。
- 人口、岗位只按街区算（现在已经基本是）。
- 格子失守时建筑退回库存。
- 玩法先不变：建筑还不能挪，街区还是地图给的。读数应和 M2 的基线接近。

**3b 自由重摆和玩家圈街区**

- 命令：挪建筑、交换两格的建筑、圈街区、解散街区。告急的格子不能挪。
- 街区数量和大小的上限（固定数字）。
- 重划时信任跟着居民走。
- 地图生成不再给街区。

**3c 类别、属性和联动**

- 建筑归到六个类别；补缺的建筑。
- 格子加地形效果和“曾经的用途”。
- 街区属性按计数自动算出，可以有多个；进度显示。
- 三层联动：建筑和地块、建筑和邻格（含少量负面）、建筑和街区。
- 属性决定候选的职业，档位决定品质；双属性出混合职业。
- 守城建筑的作用范围改成所在街区的全部边界格。
- 军械面板取消，数值并进工坊和守备的档位。

**3d 自动摆放和建筑升级**

- 自动摆放：按街区定位和钉子摆。先做简单的贪心。
- 建筑三级，第三级二选一。
- 信任开政策槽，政策按属性给。
- 加工链：工坊吃废材出零件；仓库上限改由市集建筑给。

**评估工具**

- 机器人摆城市用自动摆放；另做一个搜索布局的办法，量手动能比自动好多少。
- 街区的分布（单、双、三属性各多少）、六个类别的占比、资源流会不会卡死。
- `builder` 和 `tactician` 两个人格都重写规则，跑同样的局。

**测试**

- 任意重摆、重划以后，人口、信任、库存的总量守恒。
- 属性计数和面板显示一致。
- 告急格上的建筑挪不动；失守后建筑在库存里。
- 自动摆放的结果总是合法的。

**节点 M3**

| 检查 | 标准 |
|---|---|
| 布局深度 | 搜索出的布局比自动摆放明显好；只好一点说明联动太弱 |
| 属性分布 | 双属性中档常见，双属性高档少见但做得到 |
| 类别 | 没有哪一类永远不建，也没有哪一类占掉大半 |
| 两侧过墙 | `builder` 和 `tactician` 都能过每道墙，总分差距在区间内 |
| 平台 | M1 的平台和收敛仍然成立 |
| 试玩 | 重摆城市是有意思的，不是负担；自动摆放够用 |

**和阶段 2 对调的话**：城市可以先做，但“两侧都能过墙”那一条要等阶段 2 做完才能验证，M3 要拆成两半。

## 阶段 4：零件供给

**开发**

- **研究**：一种研究点；战斗和城市两副牌，三选一；不在时攒到上限、待选的卡等着。现有的研究池按深度开放的规则去掉。
- **仿制**：拆解得图纸，工坊造同款；图纸也进研究的战斗牌。
- **碎片**：和某一族战斗攒碎片，花碎片开发这一族的反制。
- **核心**：每个源一个首领战，带一条独有的规则；打下来可以占领并开发对应科技；这一族在来潮里的压力下降。
- **新标签和反应**：每族一种自己的标签和几条新反应；要靠这一族的队员或仿制的装备拿到手里才能用。反应图鉴显示空位。
- 加第三族。

**评估工具**

- 发现的节奏：新标签、新反应、新族各在什么时候出现。
- 各人格一局打下几个核心、在什么时候；核心是“大”级爽点。
- 仿制和掉落各供了多少装备。
- 机器人学会：选牌、仿制、用碎片、打核心。

**节点 M4**

| 检查 | 标准 |
|---|---|
| 高潮 | `greedy` 一局至少打下一个核心；后半局有“大”级爽点 |
| 发现 | 不同种子发现的反应不一样；一局内发现分布在前中后段 |
| 两条来路 | 四种资源和装备，城市和战斗两条路都有人格在用 |
| 回访 | 每次回访有东西看的比例不低于现在的基线 |
| 试玩 | 有“这个组合居然能这样用”的时刻 |

## 阶段 5：收菜的内容

**开发**

- **刷新点**：事件、战斗、物资，只刷在看得见的范围；不过期，数量有上限，可以手动删除。
- **派遣**：替补去处理刷新点；外面的战斗输了会受伤。
- **切磋**：地盘内的刷新战斗，没有后果。
- **三态迷雾**：未知、有迹象、看清；感知范围由学术建筑和队员扩大；开局提示本局有哪类特殊异界格。
- **特殊异界格**：种类每局随机，带固定特殊队员的招募。现有的三名特别队员改成从这里来。
- **异界特殊建筑**：放在领地内的异界格上，产晶体，出异界居民。
- **障碍**：部分格子的第二个建筑位；清障科技进研究的城市牌。

**评估工具**

- 机器人有处理刷新点的规则；量每次回访能处理几个、收益占多少。
- 刷新点攒到上限以后局面不变（并进收敛检验）。

**节点 M5**

| 检查 | 标准 |
|---|---|
| 收菜 | 几分钟的回访里有两三件可做的事，不需要深决策 |
| 不错过 | 离开很久回来，刷新点停在上限，没有损失 |
| 迹象 | 探索方向和迹象相关，不是盲走 |
| 试玩 | 每天上线几次，不觉得是在打卡 |

## 阶段 6：轮回

**开发**

- **收束**：结算总分；挑队员和道具（含图纸）带走，特殊队员名额另算。现有的封存机制改造成这个。
- **难度条件**：开局勾选，可以叠加；分数乘系数，同榜记录勾了哪些。
- **总部部门**：七个部门，取代前面各阶段用的固定上限；升级要资源也要达成条件；一局升不满；解锁过的种类跨局保留。
- **转化异界格**：打下过核心的族才能转。
- 开局流程：选条件、选带来的人和物。

**评估工具**

- 支持连跑多局：带走什么、勾什么条件由机器人决定。
- 量：带走的东西让下一局快多少；每个难度条件实际让分数掉多少，和系数对不对得上；部门的升级顺序是否因人格而不同。

**节点 M6**

| 检查 | 标准 |
|---|---|
| 系数 | 每个难度条件的系数略高于它实际造成的分数损失 |
| 逐局上升 | 机器人连跑几局，乘了系数的分数逐局上升 |
| 部门 | 不同人格升出不同的顺序 |
| 试玩 | 完整玩过两局以上；第二局开头不无聊；挑什么带走是个值得想的问题 |

## 网页

- 阶段 0 到 6 期间，网页只保证能编译、能打开。
- **W1**（M3 之后）：棋盘、街区、建筑重摆的界面。这是最需要图形的部分，文字版玩布局很吃力。
- **W2**（M6 之后）：其余全部补齐。
- 如果你想更早在网页上玩，W1 可以提前到阶段 3 的 3b 之后，代价是 3c、3d 的界面要改第二次。

## 内容清单在哪个阶段定

设计文档里还开着的内容问题，不单独排期，跟着用到它的阶段定：

| 内容 | 在哪定 |
|---|---|
| 计入威胁的权重、仓库上限 | 阶段 1 |
| 有几族、每族三层的内容 | 阶段 2 先两族，阶段 4 加第三族 |
| 现有设施归类、邻格联动清单、街区上限和档位门槛、政策清单 | 阶段 3 |
