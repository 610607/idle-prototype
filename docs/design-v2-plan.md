# 设计 v2：重构、开发和测试计划（草稿）

2026-11-28。把 [总纲](design-v2-outline.md)、[经营系统](design-v2-city.md)、[战斗系统](design-v2-combat.md)、[开局和节奏](design-v2-opening.md) 拆成有先后的阶段，每个阶段写清楚重构什么、开发什么、怎么测、过了什么算完成。

不写日期。规模用小、中、大表示，只用来比较各阶段。

## 进度和这次重排

- **阶段 0 已完成。阶段 1 上半已合进主干，做到节点 M1 为止。**
- 2026-11-28 重排了阶段 2 以后的顺序，原因有三：
  1. 设计加了一套语法（四样东西、五个动词，见总纲），城市和战斗要共用一套标签词汇和反应表。这是地基，要在分族和城市之前做。
  2. 血量跨战斗保留、医疗资源、复活是新定的，会改掉“挂机进攻没有损失”这条，要早做早验证。
  3. 开局节奏从“重构完成后再做”提前到阶段 3。它需要改时钟的刻度和评估的分辨率，越晚改越贵；而且之后每个阶段的试玩都从开局开始，开局不对，后面的试玩结论都偏。
- 原来的阶段 2 到 6 内容基本不变，顺延成阶段 4 到 8。

## 计划的三个前提

1. **文字版先行，网页后跟。** 每个阶段只做引擎、文字版、评估工具和文字资源；网页只保证能编译、能打开，新东西不显示。网页在两个节点集中补（见“网页”一节）。开局阶段是例外，见阶段 3。
2. **战斗（阶段 4）排在城市（阶段 5）前面。** 两者可以对调，代价见阶段 5 的说明。
3. **在现有代码上分阶段改，不另起一套。** 战斗核心、时钟、存档、随机留用；每个阶段结束时游戏都能玩、评估都能跑。

## 现状

- 引擎加评估工具约两万两千行。战斗核心 `mech/combat.rs` 约 2700 行，基本留用。
- “环”出现在 29 个文件里：地图生成、敌人强度、来潮、研究池、分数、特殊人物、评估指标。
- 评估目标 `engine/eval/goals.json` 全部按 168 小时和环写的，参考玩家是 `greedy`。
- 街区由地图给定（`District.tiles`），人口、信任、人才挂在街区上；格子的用途是“民居或设施”（`TileUse`），一格一个，定了不能挪。
- 客户端两个：文字版 `client/textui.rs`（约 2000 行）和网页。

## 每个阶段都要做的

来自项目约定，不在各阶段里重复写：

- 新命令、新信息、新预演同时进文字版；`textui::reach`、`textui::samples`、`cli.cmd.*` 补齐。
- 玩家看得到的文字进 `locales/`，数字进 `balance.json`。
- 新系统接进评估：指标登记到 `metrics.json`，机器人会用它，合格区间进目标文件，模型系数补上。
- 新词条跑 `eval price --bless`；新事件 key 在 `payoff_classes.json` 归类。
- 存档结构变了就把 `SAVE_VERSION` 加一，不写迁移。
- 试玩协议的观察或行动有不兼容的改动，把 `protocol` 加一并写进 `docs/eval-interface.md`。
- `cargo fmt`、`cargo test`；重编 WebAssembly 并提交 `pkg/`；`npx tsc --noEmit -p .` 要过。
- 阶段结束时更新 `docs/play-guide.md` 和对应的设计文档，把“还没实现”改成实际状态。
- 开局不能变慢：阶段 3 之前，第一个可感爽点的时刻（`payoff.hook_h`）不晚于 v1 基线；阶段 3 之后，开局的形状指标不退步。
- 新想法先问它是哪个动词的实例（总纲的设计语法），能用现有规则表达的不加新规则。

## 每个节点的通过标准

每个阶段的节点都由三部分组成，三部分都满足才算过：

1. **测试**：`cargo test` 全过，包括这个阶段新加的。
2. **评估**：这个阶段列出的指标落在区间内，新基线已经 `--bless`。
3. **试玩**：你自己用文字版玩过，加上一批 LLM 试玩（每批最多 3 个同时跑）。分工是：机器人管数值，算出来的指标管节奏的形状，LLM 管看不看得懂和打法分化，好不好玩由你判断。

节点没过时，先回到设计文档改设计，不带着问题进下一阶段。

## 阶段 0：准备（已完成）

不改玩法，只让后面的改动落在少数几个地方。

**重构**

- 给现在的版本打标签，旧基线 `engine/eval/baseline/` 另存一份，作为以后对照的 v1。
- **把“环”收到一个接口后面。** 所有读环的地方改成问同一处：这一格的进攻难度是多少、这一格的来潮强度是多少、研究池开到哪。阶段 1、4 换实现时只改这一处。
- **把分数收成一个函数。** 现在分数的各项权重已经在 `balance.json` 的 `score` 里；把计算集中到一处，输出各项明细。阶段 1 的威胁要读它。
- 地图生成里写死的波数、每波人数挪进 `balance.json`（原型 v2 的遗留问题）。

**评估工具**

- `eval run` 支持不定长：跑到给定的停止条件为止，不只按小时数。
- 目标文件支持“按平台算”的写法，和按小时的写法并存。旧目标保留。

**测试和节点 M0**

- `eval run greedy` 的读数和旧基线一致（同样的种子，逐项相等）。
- 文字快照前后逐字一致。
- 不需要试玩。

**结果（2026-11-28）**

- v1 是提交 `1770a5a`。`v1` 标签推不上去（代理拒绝推标签），只记在这里；旧基线另存在 `engine/eval/baseline-v1/`。
- M0 通过：`greedy` 3 个种子 × 72 小时，213 项指标逐项相等；文字快照逐字一致。
- 顺带发现：旧的分数里有随时间累加的项（守住的来潮、自给时长、最远深度），`greedy` 跑到 240 小时还在涨，没有平台。阶段 1 把分数换成“现在手里有的”。

## 阶段 1：威胁跟分数走，打不过就停（进行中）

上半已经合进主干：威胁跟统计分数走、仓库上限、路线墙前停下、手动硬打。剩下的是评估和节点 M1。**做到 M1 就停，不接着开下一阶段**，因为后面的阶段已经按新模型重排。

**开发**

- **统计分数**：建好的、练好的按高权重，库存按低权重。权重进 `balance.json`。
- **来潮强度读统计分数**，取代按环查的来潮表。
- **仓库上限**：先用固定数字，每种资源分别计。
- **路线打不过就停**：出发前预演，没把握的格子不打，队伍转去巡逻。巡逻的收益要低于推进。
- **手动硬打**：一条命令，输了全队撤回休整。
- 文字版显示：统计分数和明细、威胁读数、每支队伍停在哪、为什么停。

**暂时不动**

- 进攻难度仍然按环（阶段 4 换成异界源）。
- 军械面板留着（阶段 5 并进街区档位）。

**评估工具**

- 新指标：平台分数、到平台的时间、放手不管以后的损失、每样东西招多少威胁（`eval price` 加一列）。
- 新机器人：压分玩家（一直不涨分）。
- 新目标：平台存在；收敛；一直压分不占便宜。先压后放的藏锋打法是正当的，到阶段 2 另设人格。

**测试**

- **收敛检验**（进 `cargo test`，用小规模）：若干种子，在几个时间点取局面，之后不下任何命令再跑一段时间，损失不超过上限，局面不再变化。
- 仓库到上限后，统计分数和威胁都停住。
- 预演说能赢的格子，实际一定赢（战斗是确定的，这条应该恒成立）。

**节点 M1**

| 检查 | 标准 |
|---|---|
| 平台 | `greedy` 的分数在各种子上都会停住，不会一直涨，也不会涨到一半崩掉 |
| 收敛 | 放手不管，损失不超过上限 |
| 压分 | 压分玩家的最终分数低于 `greedy` |
| 挂机进攻 | 挂机期间进攻没有任何损失（阶段 2 起改成：损失只有药，且不低于保留线） |
| 试玩 | 离开一两天回来，局面没有变坏；能看懂队伍为什么停 |

**这个节点可能推翻什么**：如果怎么调权重都没有平台（一直涨或者一碰就崩），“威胁跟分数走”这条要回到设计上重谈。所以它排第一。

**M1 结果（2026-11-28，未全部做完，按要求先停在这里）**

| 检查 | 结果 |
|---|---|
| 平台 | 过（旧规则下 2 个种子）：`greedy` 在第 180、191 小时停住，平台分数 2474、2649，没有中途回落（`score.drop` 0）。告急格不计分以后没有重跑 |
| 收敛 | 改了以后待测。旧规则下放手 48 小时，路线一仗不输、一格不丢，但平均有 6.5 格（第 24 小时起）和 24.5 格（第 72 小时起）掉进告急。于是改成告急格不计入分数和威胁，探针改记新掉告急的比例（`handsoff.alerted`）和第二天的失守（`handsoff.day2_lost`）；`cargo test` 的收敛检验加了“最后一天不再新掉告急”，已经通过。`hands_off` 目标里新掉告急的上限还没定 |
| 压分 | 待测：压分玩家的运行中途停了 |
| 挂机进攻 | 过：放手不管的两天里路线没有打输过（`handsoff.trip_lost` 0），预演能赢的格子实际都赢（`cargo test`） |
| 试玩 | 第二轮基本过：离开一天回来不再变坏；队伍为什么停，“没收益只巡逻”看得懂，“前面打不过”有一位没看懂，已改说明，还没再试 |

- **第一轮试玩没过**（三位 Haiku，每 24 小时回来一次，`engine/eval/sessions/2026-11-28-m1/`）：三局都是刚占下、没人驻扎的第 1 圈格子守不住来潮，威胁为 0 也守不住，可是占领那一刻看不到这个后果。三局失守 12、16、25 次，终局告急 0、4、4 格，8 次回访里记“失望”的有 4、4、5 次。所以问题不在“威胁跟分数走”，在“坏事要能提前看见”（总纲原则 5）。
- **改了什么**：可占领那一行写占下后守不守得住；要人驻扎时写出谁能守住（先挑闲着的，没有才从小队里挑），菜单和格子面板多一项“占领并派某某驻扎”。告急格不计入分数和威胁。仓库上限显示出来，满了标出。巡逻和停下的说明写清楚该怎么办。
- **第二轮试玩**（同样三人、同样种子，`engine/eval/sessions/2026-11-28-m1b/`）：失守 0、0、4 次，终局告急 0、0、0 格，记“失望”的 0、2、2 次。唯一的失守是扩张征服用普通“占领”占了一格要人驻扎的地，没派人，第二天只好放弃。
- **没做的**：`greedy` 8 个种子的平台运行和压分玩家的运行中途停了，新基线没有 `--bless`，其余 5 个人格的基线还是旧规则下的；按计划，你自己用文字版玩一次也还没做。

## 阶段 2：状态保留和统一标签

设计语法的地基。范围故意收窄：只做血量、标签、医疗这一条线，不做通用引擎。

**重构**

- **一套标签词汇、一张反应表。** 现有的战斗标签和反应表作为起点；建筑带的标签（现在守城战里已经有）并进同一张表。数据层放词汇和反应，机制层只有一处读它。
- **队员的状态跨战斗保留**：血量和标签存在队员身上，不在战斗结束时清空。存档结构变，`SAVE_VERSION` 加一。
- 路线的每一步改成“和这个位置上的东西碰一次”：敌方格子是一场战斗，自己的格子是建筑的效果。

**开发**

- **医疗资源**：新的一种资源。先由现有的诊所产，战斗少量掉落；有仓库上限。
- **治疗**：消耗按缺的血量百分比指数增长，底数进 `balance.json`。自动用药的两条线（血量线、保留线）。
- **路线药不够就停**，和“打不过就停”并列，文字版显示停下的原因。
- **倒下和复活**：倒下的回家读条；全灭强制传回、固定时间复活、丢一部分战利品。现场复活的技能和道具先各做一种。
- **路线经过医疗建筑**时治疗。其他类别留到阶段 5。
- **带伤的队员按低权重计入统计分数。**
- 文字版：每名队员的血量和身上的标签、医疗库存、预计这条路线要耗多少药、队伍为什么停。

**评估工具**

- 新指标：每格耗药、药的收支、因为药停下的时间占比、全灭次数、复活等待占比。
- 机器人学会设两条线；新人格或新策略各走一种后勤打法：常规、残血（藏锋）、复活、轮换。
- 模型：把耗药并进节奏模型（每格耗时 × 格数之外，多一个每格耗药 ÷ 产药）。
- M1 的“挂机进攻没有任何损失”改成“损失只有药，且不低于保留线”。

**测试**

- 状态守恒：不治疗时，战斗结束的血量和标签等于下一场开始的。
- 预演包含耗药；预演说够的路线，实际不会中途断药。
- 收敛检验仍然成立：放手不管，药停在保留线，队伍停住，局面不再变。
- 指数消耗下，勤治的总耗药低于拖着治。

**节点 M2**

| 检查 | 标准 |
|---|---|
| 收敛 | M1 的平台和收敛仍然成立 |
| 后勤打法 | 常规、残血、复活三种打法，最终分数都在参考玩家的一个区间内；没有哪一种碾压 |
| 一直压分 | 一直带伤不治的机器人，最终分数低于先压后放的 |
| 药是约束 | 药在一局里有一段时间是瓶颈，但不是从头卡到尾 |
| 标签保留 | 至少有一条路线，调换两格的先后会改变结果 |
| 试玩 | 看得懂药花在哪；“带着伤再推一格还是回去治”是个值得想的问题，不是烦人的事 |

**这个节点可能推翻什么**：如果医疗只是多了一个要盯的数，没有带来选择，就把自动用药做得更省心，或者退回“受伤只是休整”。

## 阶段 3：开局

依据是 [开局和节奏](design-v2-opening.md)。排在这里是因为它要动时钟和评估的分辨率，而且之后每个阶段的试玩都从开局开始。

**重构**

- **时钟的刻度变细。** 现在模拟每 5 分钟一步；开局要以秒计。先定方案（全程细刻度，还是开局细、之后粗），再动 `mech/sim.rs`，引擎层尽量不动。
- 评估的统计和爽点时间轴支持秒级。
- 试玩协议的日程改成前密后疏，`protocol` 加一。

**开发**

- **揭示链**：开局只有一件事可做，每做成一件露出下一样。先用现有内容排出九步（见开局文档的表），不为它新造系统。
- **手动派遣**作为开局的第一个动作；自动之后保留为手动入口。
- **头几层自动化**：路线自己跑、按线自动用药、岗位自动填、研究队列。每层对应一个总部部门的成立；部门在这里只做“成立”，升级留到阶段 8。
- **提前露出**：下一样东西看得见、买不起、显示还差多少。
- **成本曲线**：占格和建筑的成本按倍数涨；研究价格从线性改成阶梯。倍率先用 `eval pace --patch` 和模型算。
- 网页：开局是最看手感的一段，文字版试不出“几秒一次反馈”。这一阶段网页要跟着做到能玩开局的程度。

**评估工具**

- 形状指标登记到 `metrics.json`：开局密度（头 1、5、15、60 分钟的新东西数）、相邻里程碑的间隔比、每个大爽点的幅度、每种手动操作被自动化前的重复次数、第一道硬墙的时刻。
- `goals.json` 里按小时、按环等间隔写的目标，换成按对数时间写的。
- 机器人能走完揭示链；开局阶段按秒决策。
- LLM 试玩：每次回访多问“现在会继续玩还是关掉，多久后回来”；用比较代替打分；另设只看时间轴的审阅者角色。
- 记录你自己的游玩（什么时候上线、玩多久、哪一刻有意思或无聊），用来校准上面的指标。

**测试**

- 揭示链的每一步都可达：参考机器人在规定时间内走完。
- 每个按钮出现时，离买得起不超过规定的倍数。
- 细刻度和粗刻度跑同一段，结果一致或差在规定范围内。

**节点 M3**

| 检查 | 标准（数字是初步的，见开局文档） |
|---|---|
| 第一个结果 | 10 秒内 |
| 头 1 分钟 | 至少 3 样新东西 |
| 第一层自动化 | 5 分钟内 |
| 头 15 分钟 | 至少 10 样新东西 |
| 间隔比 | 相邻里程碑的间隔比在 1.3 到 2 之间，不是接近 1 |
| 硬墙 | 第一道硬墙不早于前几层自动化到位 |
| 后段 | M1、M2 的平台、收敛、后勤打法仍然成立 |
| 试玩 | 你自己从头玩一遍，头十五分钟不想关掉；之后是自己想去找提升，不是被卡住 |

**这个节点可能推翻什么**：现有内容排不出足够密的揭示链，说明开局需要专门的内容（更短更简单的头几场战斗、更便宜的头几座建筑），要回到开局文档补设计。

## 阶段 4：敌人分族，来潮是敌人的路线

**重构**

- 进攻难度的接口换实现：从“第几环”换成“离哪个异界源多远、源多强”。
- 地图生成放置异界源；格子记下属于哪一族、带到第几层。
- `Squad` 加学说槽；学说从全局生效改成按队装备。
- 评估里按环的指标（进第几环的时间、前线胜率）换成按源、按层的。

**开发**

- **先做两族**，用现有的标签。现有的两种世界修正（偏震荡、偏侵蚀）是现成的起点。每族三层：惯用标签、抗性和弱点、一条行为规则。
- **行为规则**做成数据层的效果种类，机制层读它；能用现有效果种类表达的就不加新的。
- **出战总名额**（先用固定数字）由玩家分到各队；一队最多六人。
- **战报诊断**：输在哪一步，谁被什么打死，哪个标签没人处理；给出战术规则的修改建议。
- **图鉴**：遇到过的族，逐层揭开。
- **来潮改成敌人的路线**：和玩家的路线走同一套规则，敌人的血量和标签跨格保留；预演、战报、诊断和进攻共用。往里走多深在这里定。
- 现有的二十种敌人、二十八条学说归到两族和通用池里。

**评估工具**

- 每族的打法数：枚举或搜索队伍构成，数能赢的有几种不同的构成。
- 墙的位置、停多久、用五档手段里的哪一档过的。
- 默认规则和搜索出的规则的差距。
- 机器人学会：分名额、按族换学说、看诊断调队。`tactician` 人格用上这些。

**测试**

- 每族每层至少有一支测试队能赢、一支不能赢（防止某一层其实不起作用）。
- 两族混编的格子，敌人构成符合数据。
- 六人队、三人队的战斗都确定。

**节点 M4**

| 检查 | 标准 |
|---|---|
| 打法数 | 每族在近处那一层，至少三种不同构成的队伍能过 |
| 墙 | 一局里出现多道墙；没有只靠等就过去的墙 |
| 默认规则 | 只用默认规则的机器人能过标准难度下所有的墙 |
| 集中和分散 | 两种分名额的办法分数都过得去 |
| 攻守对称 | 来潮和进攻用同一套预演和战报；守城的结果和预演一致 |
| 试玩 | 撞墙时知道该琢磨什么；过墙时觉得是自己想出来的 |

**这个节点可能推翻什么**：如果现有的战斗引擎做不出“三种打法”，要么加标签和反应的数量，要么调整三层的设计。

## 阶段 5：城市背包

工程量最大的一块，内部分四步，每步结束都能跑。

**5a 重构：人口和建筑脱离格子**

- 建筑从“格子的用途”改成物品：有库存，放在格子上，可以取下。
- 人口、岗位只按街区算（现在已经基本是）。
- 格子失守时建筑退回库存。
- 玩法先不变：建筑还不能挪，街区还是地图给的。读数应和 M4 的基线接近。

**5b 自由重摆和玩家圈街区**

- 命令：挪建筑、交换两格的建筑、圈街区、解散街区。告急的格子不能挪。
- 街区数量和大小的上限（固定数字）。
- 重划时信任跟着居民走。
- 地图生成不再给街区。

**5c 类别、属性和联动**

- 建筑归到六个类别；补缺的建筑。
- 格子加地形效果和“曾经的用途”。
- 街区属性按计数自动算出，可以有多个；进度显示。
- 三层联动：建筑和地块、建筑和邻格（含少量负面）、建筑和街区。
- 属性决定候选的职业，档位决定品质；双属性出混合职业。
- 守城建筑的作用范围改成所在街区的全部边界格。
- 军械面板取消，数值并进工坊和守备的档位。
- **类别用阶段 2 的统一标签词汇**：街区属性是同种标签叠到门槛，不另写一套计数。
- **路线经过城市**：阶段 2 只做了医疗一种，这里补齐每类建筑被路过时发生什么。

**5d 自动摆放和建筑升级**

- 自动摆放：按街区定位和钉子摆。先做简单的贪心。
- 建筑三级，第三级二选一。
- 信任开政策槽，政策按属性给。
- 加工链：工坊吃废材出零件；仓库上限改由市集建筑给。
- 自动摆放并入开局的第 5 层自动化（见 [开局和节奏](design-v2-opening.md)）。

**评估工具**

- 机器人摆城市用自动摆放；另做一个搜索布局的办法，量手动能比自动好多少。
- 街区的分布（单、双、三属性各多少）、六个类别的占比、资源流会不会卡死。
- `builder` 和 `tactician` 两个人格都重写规则，跑同样的局。

**测试**

- 任意重摆、重划以后，人口、信任、库存的总量守恒。
- 属性计数和面板显示一致。
- 告急格上的建筑挪不动；失守后建筑在库存里。
- 自动摆放的结果总是合法的。

**节点 M5**

| 检查 | 标准 |
|---|---|
| 布局深度 | 搜索出的布局比自动摆放明显好；只好一点说明联动太弱 |
| 属性分布 | 双属性中档常见，双属性高档少见但做得到 |
| 类别 | 没有哪一类永远不建，也没有哪一类占掉大半 |
| 补给线 | 把建筑摆在出征路上的布局，比不考虑路线的布局明显好 |
| 两侧过墙 | `builder` 和 `tactician` 都能过每道墙，总分差距在区间内 |
| 平台 | M1 的平台和收敛仍然成立 |
| 试玩 | 重摆城市是有意思的，不是负担；自动摆放够用 |

**和阶段 4 对调的话**：城市可以先做，但“两侧都能过墙”那一条要等阶段 4 做完才能验证，M5 要拆成两半。

## 阶段 6：零件供给和“变”

**开发**

- **研究**：一种研究点；战斗和城市两副牌，三选一；不在时攒到上限、待选的卡等着。现有的研究池按深度开放的规则去掉。
- **仿制**：拆解得图纸，工坊造同款；图纸也进研究的战斗牌。
- **碎片**：和某一族战斗攒碎片，花碎片开发这一族的反制。
- **核心**：每个源一个首领战，带一条独有的规则；打下来可以占领并开发对应科技；这一族在来潮里的压力下降。
- **新标签和反应**：每族一种自己的标签和几条新反应；要靠这一族的队员或仿制的装备拿到手里才能用。反应图鉴显示空位。
- 加第三族。
- “变”的其他实例（退役队员变物品、俘虏、拆词条）从 [战斗](design-v2-combat.md) 和 [经营](design-v2-city.md) 文末的例子里挑，按语法检验后再加，不预先承诺。

**评估工具**

- 发现的节奏：新标签、新反应、新族各在什么时候出现。
- 各人格一局打下几个核心、在什么时候；核心是“大”级爽点。
- 仿制和掉落各供了多少装备。
- 机器人学会：选牌、仿制、用碎片、打核心。

**节点 M6**

| 检查 | 标准 |
|---|---|
| 高潮 | `greedy` 一局至少打下一个核心；后半局有“大”级爽点 |
| 发现 | 不同种子发现的反应不一样；一局内发现分布在前中后段 |
| 两条来路 | 四种资源和装备，城市和战斗两条路都有人格在用 |
| 回访 | 每次回访有东西看的比例不低于现在的基线 |
| 试玩 | 有“这个组合居然能这样用”的时刻 |

## 阶段 7：收菜的内容

**开发**

- **刷新点**：事件、战斗、物资，只刷在看得见的范围；不过期，数量有上限，可以手动删除。
- **派遣**：替补去处理刷新点；外面的战斗输了会受伤。
- **切磋**：地盘内的刷新战斗，没有后果。
- **三态迷雾**：未知、有迹象、看清；感知范围由学术建筑和队员扩大；开局提示本局有哪类特殊异界格。
- **特殊异界格**：种类每局随机，带固定特殊队员的招募。现有的三名特别队员改成从这里来。
- **异界特殊建筑**：放在领地内的异界格上，产晶体，出异界居民。
- **障碍**：部分格子的第二个建筑位；清障科技进研究的城市牌。

**评估工具**

- 机器人有处理刷新点的规则；量每次回访能处理几个、收益占多少。
- 刷新点攒到上限以后局面不变（并进收敛检验）。

**节点 M7**

| 检查 | 标准 |
|---|---|
| 收菜 | 几分钟的回访里有两三件可做的事，不需要深决策 |
| 不错过 | 离开很久回来，刷新点停在上限，没有损失 |
| 迹象 | 探索方向和迹象相关，不是盲走 |
| 试玩 | 每天上线几次，不觉得是在打卡 |

## 阶段 8：轮回

**开发**

- **收束**：结算总分；挑队员和道具（含图纸）带走，特殊队员名额另算。现有的封存机制改造成这个。
- **难度条件**：开局勾选，可以叠加；分数乘系数，同榜记录勾了哪些。
- **总部部门**：补齐七个部门的升级（部门的成立在阶段 3 已经做了）；升级要资源也要达成条件；一局升不满；解锁过的种类跨局保留。
- **轮回后的开局**：带来的东西压缩轰炸期，但不让它消失；第 6 层自动化在这里解锁。
- **转化异界格**：打下过核心的族才能转。
- 开局流程：选条件、选带来的人和物。

**评估工具**

- 支持连跑多局：带走什么、勾什么条件由机器人决定。
- 量：带走的东西让下一局快多少；每个难度条件实际让分数掉多少，和系数对不对得上；部门的升级顺序是否因人格而不同。

**节点 M8**

| 检查 | 标准 |
|---|---|
| 系数 | 每个难度条件的系数略高于它实际造成的分数损失 |
| 逐局上升 | 机器人连跑几局，乘了系数的分数逐局上升 |
| 部门 | 不同人格升出不同的顺序 |
| 开局压缩 | 第二局到第一道墙的时间明显短于第一局，但开局的形状指标仍在区间内 |
| 试玩 | 完整玩过两局以上；第二局开头不无聊；挑什么带走是个值得想的问题 |

## 网页

- 网页平时只保证能编译、能打开。
- **W0**（阶段 3 内）：开局能在网页上玩，用来试手感。只做开局用得到的界面。
- **W1**（M5 之后）：棋盘、街区、建筑重摆的界面。这是最需要图形的部分，文字版玩布局很吃力。
- **W2**（M8 之后）：其余全部补齐。
- 如果你想更早在网页上玩，W1 可以提前到阶段 5 的 5b 之后，代价是 5c、5d 的界面要改第二次。

## 内容清单在哪个阶段定

设计文档里还开着的内容问题，不单独排期，跟着用到它的阶段定：

| 内容 | 在哪定 |
|---|---|
| 计入威胁的权重、仓库上限 | 阶段 1 |
| 医疗消耗的底数、两条线的默认值、全灭的代价、带伤的权重；标签词汇怎么合成一套 | 阶段 2 |
| 揭示链每一步的内容和门槛、三条成本曲线的倍率、时钟刻度怎么过渡 | 阶段 3 |
| 有几族、每族三层的内容；来潮往里走多深 | 阶段 4 先两族，阶段 6 加第三族 |
| 现有设施归类、邻格联动清单、街区上限和档位门槛、政策清单；路线经过每类建筑发生什么 | 阶段 5 |
| 碎片能开发什么、核心的独有规则 | 阶段 6 |
| 特殊异界格和障碍的种类 | 阶段 7 |
| 带走的名额、难度条件清单、部门每级给什么、第 6 层自动化 | 阶段 8 |

## 首批做和不做

这几轮头脑风暴出的玩法，进首批的只有下面几条，其余记在战斗和经营文档文末当例子，不排期：

| 进首批 | 在哪个阶段 |
|---|---|
| 血量跨战斗保留、医疗资源、复活 | 2 |
| 标签跨战斗保留 | 2 |
| 藏锋和残血打法（带伤、库存按低权重计） | 2 |
| 保留线（药不够就停） | 2 |
| 路线经过自己的城市 | 2 做医疗，5 补齐 |
| 来潮是敌人的路线 | 4 |

## 风险

| 风险 | 在哪暴露 | 怎么办 |
|---|---|---|
| 威胁跟分数走调不出稳定的平台 | M1 | 回到设计，重谈威胁的算法 |
| 医疗只是多一个要盯的数，没有带来选择 | M2 | 自动用药做得更省心，或退回“受伤只是休整” |
| 标签统一成一套以后组合太多，评估跑不动 | 阶段 2 起 | 组合爆炸本身是要的；评估只抽样，不枚举。玩家侧失控由威胁跟分数走兜住 |
| 现有内容排不出够密的开局 | M3 | 给开局补专门的内容 |
| 时钟刻度改动牵连太广 | 阶段 3 | 先定方案再动；只在开局用细刻度是退路 |
| 现有战斗做不出每族三种打法 | M4 | 加标签和反应，或者简化三层 |
| 布局只有一个最优解，或者自动摆放就够好 | M5 | 加负面联动和地块差异；仍然不行就降低城市的分量 |
| 机器人跟不上新系统，评估失真 | 每个阶段 | 每个阶段的机器人规则和功能一起做，`commands.never` 不能有新命令 |
| 文字版玩布局太吃力，试玩结论偏 | 阶段 5 | W1 提前 |
| 阶段 5 太大，中途游戏不能玩 | 阶段 5 | 按 5a 到 5d 分步，每步都能跑 |
